1. 요청 및 완료 상태
1) 최신 이미지의 미구현 4~7단계: 로컬 API/CLI/노트북으로 구현하고 격리 통합 테스트 완료.
2) 검토 지적 보완: OCSVM 등록 시 감사 모델·선택·데이터·분할·코드 확인, 고유 실행 폴더 적용.
3) 로지스틱 회귀: CN7/RG3 각각 8구성×15 C×2가중치×1001 임계값, 개발 4-fold 실험 완료.
4) RG3 CD 구간 안내: 고정 구간별 관측 위험 이력·참조/평가 표본·Wilson 구간·표본 부족 표시 구현.
5) 오늘 12:30 이후 대화 원문과 기술 기록을 이 TXT에 수록. 재현 소스·결과 ZIP 별도 제공.

2. 실제 구현과 현장 검증의 구분
현재 구현은 로컬 CSV 기반 운영 경로다. 웹 서비스·실제 DB·상시 스케줄러는 구축하지 않았다.
실제 신규 생산 배치·생산 시각·독립 검사 정답은 제공되지 않았다.
따라서 CT·CD 실행 테스트는 합성 입력을 쓴 기술 검증이며 현장 성능 검증이 아니다.
실제 runtime의 기존 IF·OCSVM 운영 포인터는 유지했다. LR은 초기 후보만 저장했다.
OCSVM/LR 자동 운영 승격은 수행하지 않았다. 현재 관찰된 성능으로 우수성을 주장하지 않는다.

4. 검증 내역
운영 통합 12개: 빈도/충돌 보존, 미정합 입력 보류, 표본 누적 대기, 지속 드리프트,
IF/OCSVM/LR/RF CT, 비라벨 CT 차단, 학습·평가 중복 차단, 검증·교체·롤백,
표본 부족 교체 차단, 모델 변조 감지, 0건을 안전으로 오인하지 않기, 기존 Test 후속평가 강제.
등록·LR 7개: 감사 원본 등록, 감사 이후 변경 차단, 임계값 불일치 차단,
분할 변경 차단, 전체 train scaler, 정상 기준 도메인 변환, 저장 예측 재현.
기존 OCSVM 6개×2데이터×2순서 = 24회 회귀 테스트 통과.
총 43회. 새 노트북 2개 새 커널 실행 완료.
LR 설정·임계값 평가 240,240행씩 총 480,480행을 독립 재검산했다.
원래 학습 결과와 동일한 최종 코드로 재실행했으며 결과 변화는 없었다.
초기 임시 구현 실행 기록도 삭제하지 않고 별도 run_id로 보존했다.

5. 이미지 1~5의 방향 변화
1번: EDA·패턴 전처리·분할·학습·후속 평가.
2번: 신규 배치 운영·현장 정답·지속 학습·배포 확장.
3번: IF 점수 기반 정렬·선택적 가중치 실험.
4번: 분포 변화와 원인 확인을 재학습의 출발점으로 변경.
5번: 별도 검사/라벨 연결 단계를 제거하고 라벨 포함 배치를 기존 전처리로 처리하는 7단계.
IF→OCSVM은 필수 직렬 모델이 아니다. 기본 독립 학습, IF 순서는 선택적 비교다.
최신 목표는 모델을 계속 덧붙이는 것보다 언제 유지·검토·재학습·교체할지 기록하는 것이다.

6. 프로젝트에서 확인한 지식과 해석
원본 CN7 1211행·RG3 1182행, 입력 24개. ID와 라벨은 모델 입력에서 제외한다.
CN7 고유 패턴606개=정상592+위험14, 충돌11·불량만3.
RG3 고유 패턴591개=정상566+위험25, 위험25개 모두 정상 기록과 공존.
동일 입력에서 결과가 다르다는 사실만으로 어느 행이 가짜인지 확정할 수 없다.
모든 충돌을 정상으로 처리하면 RG3 위험 라벨이 0개가 돼 불량 탐지 학습·검증이 불가능하다.
모든 충돌을 위험으로 처리하면 현재 최대 라벨 패턴 정책과 같다.
max(label)은 위험 이력이 있다는 뜻이며 개별 제품의 불량 확률을 뜻하지 않는다.
빈도·원래 라벨·원본 ID·행 매핑을 보존해야 제품 분포와 패턴 분포를 구분할 수 있다.
학습은 고유 패턴, 운영 감지는 제품 발생 빈도를 보존한 분포를 사용한다.
현재 원본 행 번호가 생산 시간순이라는 사실은 확인되지 않았다.
라벨/비라벨이 같은 컬럼을 가진다고 같은 표준화 좌표라고 단정할 수 없다.
비라벨은 정합 확인 후 추론·감지에만 쓰며 예측을 정답으로 바꿔 CT하지 않는다.
추론 때 scaler를 재적합하면 기준이 달라지므로 저장 변환을 사용한다.
관계식의 높은 R²는 다른 변수로 값을 예측한다는 뜻이며 불량 분류 정확도가 아니다.
이전 관계식·잔차 실험은 변수 관계를 포착했지만 안정적 불량 구분 개선은 입증하지 못했다.
이전 짧은 과거 문맥 실험도 개선을 입증하지 못했다. 실제 시간순 미확인 조건이었다.
이전 스태킹은 개발 검증의 일부 보완 효과가 Test의 안정적 개선으로 이어지지 않았다.
드리프트는 분포 변화이며 불량 증가·원인·모델 열화의 확정 증거가 아니다.
같은 모델로 과거/최근을 비교하면 데이터 변화, 같은 평가 자료로 기존/후보를 비교하면 모델 변화다.
지속 입력 변화만으로 검토할 수 있고 모델 반응 변화가 함께 있으면 근거가 강화된다.
배치 크기·드리프트 감지 윈도·재학습 자료 크기는 서로 다른 설정이다.
현재 경보선 부트스트랩은 표본 크기에 따른 경험적 기준이며 시간 의존성까지 보정하지 않는다.
불량이 드문 데이터에서 0건은 안전을 뜻하지 않는다. 분모·위험 수·불확실성을 함께 보여야 한다.
검증 데이터로 후보와 임계값을 고른 뒤 같은 검증 점수를 독립 성능처럼 제시하면 낙관적이다.
최종 재학습에서 점수 분포가 달라질 수 있지만 Test를 보고 임계값을 다시 고르면 안 된다.
등록된 모델의 해시가 맞더라도 등록 전에 잘못된 파일을 검증된 것으로 취급하면 안 된다.
고유 run_id와 감사·모델·분할·코드 연결이 있어야 버전별 근거를 추적할 수 있다.

7. 통계·모델 용어
패턴: 24개 입력값이 정확히 같은 관측을 묶은 단위.
위험 이력: 같은 패턴에서 한 번이라도 불량 라벨이 있었음.
OOF: 각 행을 학습에 쓰지 않은 fold 모델로 만든 검증 예측.
TP: 위험을 위험으로 탐지. FP: 정상을 위험으로 오탐. FN: 위험 누락. TN: 정상 유지.
Recall: TP/(TP+FN). FPR: FP/(FP+TN). Precision: TP/(TP+FP).
F1: 2TP/(2TP+FP+FN). 높은 F1이 모든 위험 탐지를 의미하지 않는다.
임계값: 점수가 이 값보다 클 때 위험으로 판정하는 경계. 본 코드는 엄격한 >를 사용한다.
클래스 가중치: 학습 손실에서 정상/위험의 비중. 임계값과는 다른 설정이다.
C: 로지스틱 규제 강도의 역방향 설정. 작은 C는 강한 규제.
계수: 변환된 입력에 대한 모델상 log-odds 변화. 물리 인과 효과나 p값이 아니다.
잔차: 실제 값과 관계식의 예상값 차이. 정상 오차 기준 조정 후에도 불량 확률은 아니다.
R²: 관계 예측의 설명력. 분류 정확도와 다르다.
TV 거리: 범주/구간 비율 차이의 절댓값 합을 2로 나눈 값.
Wilson 구간: 이항 비율의 참고 불확실성 구간. 여기서는 패턴 독립성·다중 비교를 보장하지 않는다.
CT: 원인·라벨·표본 조건 충족 후 후보 재학습. 이번 구현은 전체 재학습이다.
CD: 분리 평가로 비교한 후 해당 모델 버전만 교체. 실패·표본 부족이면 유지한다.
롤백: 저장된 이전 모델 버전으로 되돌리고 그 이유를 기록하는 작업.

KAMP 7단계 로컬 실행 가이드 — 2026-10-03

모델별 전체 재학습·분리 평가·승격·롤백을 로컬 Python API/CLI로 구현했다.

꺾쇠 항목은 실제 값으로 교체한다. --state-root <별도경로>를 전역 인자로 주면 격리 저장소로 리허설한다.
coordinates-confirmed는 운영자가 제공 좌표계/스케일 정합을 확인했다는 명시적 선언이다.
컬럼이 같다는 사실만으로 좌표 정합을 자동 판정하지 않는다.
없는 라벨을 생성하지 않는다. PassOrFail이 있다면 모두 0/1이어야 하고 출처를 기록한다.
원본 제품 ID와 빈도를 보존하고 같은 입력은 max(label) 위험 이력으로 집계한다.
배치 ID는 재사용하지 않는다. 제품 ID는 데이터셋·배치 ID와 함께 식별한다.

기준선·감지 정책
최초 기준선은 개발 패턴을 원본 제품 빈도만큼 복원한 분포다. Test는 포함하지 않는다.
값이 12종 이하이면 값별 비율, 그 외에는 참조 자료의 고정 분위수 구간을 사용한다.
범위 밖 값·변수 2개 조합·같은 버전 모델의 점수 및 예측 비율을 비교한다.
TV 거리 = 0.5 × 비율 차이 절댓값의 합.
제품 최소 200개·고유 패턴 최소 40개까지 누적하며 배치 크기와 감지 윈도를 분리한다.
완성된 윈도에 사용한 배치는 다음 윈도에서 다시 쓰지 않는다.
고유 패턴 수를 유효 표본 크기로 사용한 참조 부트스트랩 200회·최대 변화량 99% 분위수를
시험 경보선으로 사용한다. 이는 현장 시계열 의존성까지 보정한 확정 경보선이 아니다.
초과 1회 주의, 같은 기준선에서 2회 연속 초과하면 원인 검토다. 출력 변화가 없어도 입력 변화로 검토할 수 있다.
신규 패턴 비율은 참고만 하며 재학습 단독 조건으로 쓰지 않는다.

CT/CD 정책
드리프트 검토 ID, 현재 운영 기준 버전, 원인 기록, 라벨 있는 배치가 필요하다.
기존 위험 이력을 신규 정상 라벨로 덮어쓰지 않는다. 기존 corpus와 새 자료를 합쳐 최대 라벨로 집계한다.
IF·OCSVM은 정상 패턴으로 전체 재학습, LR·RF는 정상·위험 모두로 전체 재학습한다.
이번 구현은 partial_fit이 아닌 전체 재학습 경로다. 모델별 독립 후보이며 자동 승격하지 않는다.
기존 Test와 등록된 평가 패턴은 CT에서 거부한다.
기존 Test를 평가 자료로 등록하면 강제로 historical_followup 처리해 승격 근거로 사용하지 않는다.
초기 모델 지정 initialize는 검증된 우수성 선언이 아닌 명시적 비교 기준 지정이다.
평가 고유 정상 최소 30개·위험 최소 5개가 기본값이다. 표본 수 충족만으로 현장 신뢰도를 보증하지 않는다.
분류 모델은 F1 개선, Recall 유지, FPR 0.2 이하를 모두 요구한다.
IF는 동일 검사량에서 위험 발견 기대 수가 증가해야 한다. 예산 동점은 최소·최대·기대값을 함께 기록한다.
운영 정책은 Operations(policy=...)에서 변경 가능하며 평가 기록에 저장된다. Test 결과로 정책을 조정하지 않는다.
미달·표본 부족·이미 관찰한 평가이면 유지/보류한다. 통과한 해당 모델만 명시적 promote로 교체한다.
교체 후 기준선의 모델 점수 버전을 갱신하고, 이전 모델을 보존해 rollback한다.
라벨 포함 배치에는 패턴 단위 사후 지표가 저장된다. 비라벨 배치에 성능 지표를 만들지 않는다.

또한 학습에서는 고유 패턴을 사용하더라도, 운영 중 분포 변화 감시에는 **실제 제품 발생 빈도**를 유지하려는 설계입니다. 같은 패턴이 1번 나온 것과 100번 나온 것을 드리프트 감지에서 같게 취급하지 않겠다는 의미입니다.

**4. 현재 실제로 구현된 범위는 여기까지입니다.**

**5. 가장 중요한 설계 변화는 ‘드리프트 → 즉시 재학습’이 아니라는 점입니다.**

제가 이해한 현재 흐름은 다음과 같습니다.

> 신규 배치를 기존 전처리와 저장 모델로 처리  
> → 기준 분포와 비교  
> → 변화의 크기·지속성·표본 수 확인  
> → 원인과 학습 자료 확인  
> → 후보 모델 학습  
> → 같은 평가 자료로 기존 모델과 비교  
> → 통과한 모델만 교체

드리프트는 다음을 함께 보려는 계획입니다.

- 특정 값이 나타나는 비율
- 온도·압력의 구간별 비율과 기존 범위 밖 값
- 변수 조합의 비율
- 같은 버전 IF·OCSVM의 점수와 위험 예측 비율

여기서 **분포가 달라졌다는 사실은 불량 증가나 모델 성능 저하의 확정 증거가 아닙니다.** 그래서 원인 확인과 검증 단계를 둔 것으로 이해합니다. 공정 이상을 그대로 새 정상으로 학습해 버리는 것도 막으려는 구조입니다.

**6. 이미지에서 혼동하기 쉬운 부분도 확인했습니다.**

5번 이미지의 IF→OCSVM 화살표는 필수 직렬 학습으로 읽힐 수 있지만, **현재 코드의 기본값은 독립 학습**입니다. OCSVM의 `TRAIN_ORDER='original'`이 기본이고, IF 점수순 정렬은 `if_desc`라는 선택적 비교 실험입니다. 이미지 제작 기록에도 두 모델 사이 화살표를 제거한다는 수정 의도가 적혀 있습니다.

또한 최신 5번에서는 다음 원칙이 분명합니다.

- 파일 행 순서를 실제 생산 시간으로 가정하지 않음
- 신규 배치 추론 때 스케일러를 재학습하지 않음
- 비라벨은 스케일 정합 확인 후 추론·감지에만 사용
- 비라벨을 예측 라벨로 바꿔 재학습시키지 않음
- 초기 모델의 최종 적합과 운영 중 CT를 구분함

**제가 이해한 프로젝트의 차별점은 “특별한 모델로 무조건 높은 정확도를 만든다”보다, “데이터의 한계를 보존하면서 모델을 언제 유지하고 언제 바꿀지 근거를 남긴다”는 데 있습니다.** 현재는 그 구조의 초기 학습·저장 기반까지 구현됐고, 운영·드리프트·재학습·교체 부분은 앞으로 검증하며 구현할 설계입니다.
