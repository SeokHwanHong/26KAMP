KAMP 사용자 요청사항 통합 작업 프롬프트

용도: 내가 요청했던 작업을 다른 AI 또는 팀원에게 전달하기 위한 재작성본이다.
원문 그대로의 대화록은 KAMP_20261003_1230이후_사용자프롬프트.txt를 참고한다.
이미 완료된 작업도 있으므로 현재 소스를 확인한 후 누락·오류만 보완한다.

================ 복사할 프롬프트 시작 ================

현재 진행 중인 KAMP 제조 공정 데이터 분석 프로젝트를 확인하고, 아래 작업을 끝까지 수행해줘.
프로젝트 위치는 D:\workspace\kamp야. ZIP으로 전달받았다면 압축 해제한 프로젝트를 기준으로 작업해.

나는 파이썬 문법보다 데이터의 구조적 문제, 통계적 의미, 모델링 방향과 전체 아키텍처를 먼저 이해하고 싶어.
모델을 복잡하게 만드는 것보다 왜 이 학습·판단·검증 방식이 필요한지 설명할 수 있어야 해.
현업에서 믿고 사용할 수 있는 범위와 한계도 근거를 가지고 설명해줘.
실험은 반드시 실제 코드로 실행하고, 실행하지 않은 결과를 추정해서 보고하지 마.

1. 최신 프로젝트와 설계 변경 이력 파악
- 현재 폴더·소스·노트북·문서·실험 결과와 기존 변경사항을 먼저 확인해.
- 첨부한 KAMP_아키텍처_1.png ~ KAMP_아키텍처_5.png를 변경 이력으로 읽고, 가장 최근의 5번 이미지를 현재 설계 기준으로 삼아.
- 이미지를 제공받지 못했다면 현재 설계 문서를 확인하고, 이미지와 직접 대조하지 못했다는 점을 밝혀.
- 과거의 이상 점수 정렬·가중치 중심 설계와 현재 드리프트 기반 운영·재학습 설계를 구분해.
- 실제 구현된 부분, 일부 구현된 부분, 미구현 부분, 현장 데이터로 검증하지 못한 부분을 코드 근거와 함께 정리해.

2. 미구현 부분 구축 및 기존 문제 수정
- 최신 구조의 데이터 준비 → EDA·전처리 → 초기 모델·기준선 → 배치 유입·추론 → 드리프트 감지 → 모델별 재학습 → 검증·교체 흐름을 확인해.
- 누락된 부분을 기존 구조에 맞게 구현하고, 모델링 검토에서 발견된 오류·누수·기록 누락을 수정해.
- 배치 입력 검증, 저장 전처리 재사용, 제품 ID·발생 빈도 보존, 점수·예측·모델 버전 기록을 연결해.
- 드리프트는 변화의 크기·지속성·표본 수를 확인하고, 정상 유지·관찰·원인 검토로 판단하도록 해.
- 변화가 있다고 자동으로 재학습하거나 공정 이상을 새로운 정상으로 흡수하지 마.
- 라벨과 표본 조건을 충족하면 모델별 후보를 만들고, 분리된 동일 평가 자료로 기존 모델과 비교해.
- 기준을 통과한 해당 모델만 교체할 수 있도록 하고, 표본 부족·미달 시 유지 및 롤백 경로를 마련해.
- 이미 구현된 기능은 중복 작성하지 말고 동작과 연결 상태를 검증해.

3. 내 담당인 로지스틱 회귀 모델 테스트 수행
- 현재 로지스틱 구현과 학습 흐름을 검토하고 CN7·RG3 각각 테스트해.
- 기존 고정 분할과 개발 데이터 4-fold 검증 정책을 유지해.
- 전처리·파생변수·스케일러는 해당 fold의 학습 데이터에서만 적합해.
- 모델 설정과 임계값은 개발 OOF 결과로 선택하고, Test를 보고 다시 조정하지 마.
- 기존 실험이 재현 가능한지 먼저 확인하고, 변경으로 재실험이 필요하면 새 실행 폴더에 저장해.
- OOF와 Test의 F1·Recall·Precision·오탐률·TP·FP·FN·TN, 위험 표본 수를 함께 보고해.
- 설정·임계값·분할·코드·저장 모델·예측 결과의 연결과 재로딩 재현성을 검증해.
- 계수와 변수 관계를 설명하되, 인과관계나 불량 원인으로 단정하지 마.
- 결과가 나쁘면 그대로 보고하고, 개발 점수와 실제 활용 가능성을 구분해.

4. RG3의 데이터 분포를 이용한 구간 안내 구현
- 이전 요청에서 쓴 gn3는 이 프로젝트의 RG3를 의미해.
- RG3는 CN7보다 위험 표본 확보와 구분이 어렵다는 점을 고려해.
- CD 검토에서 변수 구간·조합별로 위험 이력이 관찰된 범위와 표본 부족 범위를 안내하도록 해.
- 학습 자료에서 정한 구간을 기준으로 전체 표본 수, 고유 패턴 수, 위험 패턴 수, 관측 비율과 불확실성을 표시해.
- 학습 자료의 관측 결과와 독립 평가 결과를 구분해.
- 불량이 관측되지 않은 구간을 안전 구간이라고 확정하지 마.
- 동일 입력의 정상·불량 충돌만으로 가짜 라벨이나 외부 원인을 확정하지 마.
- 안내는 관측된 위험 이력과 추가 검사 필요성에 관한 것이며, 실제 불량 발생 확정 범위나 인과 설명으로 표현하지 마.
- 이 안내를 실제 배포 가능성 판단과 연결하되 부족한 표본을 숨기지 마.

5. 테스트 흐름과 전체 워크플로우 검증
- 초기 학습부터 배치 추론·드리프트·재학습·후보 비교·교체·롤백까지 테스트 흐름을 문서화해.
- 입력 오류, 비라벨 처리, 표본 부족, 학습·평가 중복, 모델 파일 변경, 임계값 불일치도 확인해.
- 현재 통합 실행기 python 03.modeling/tests/run_checks.py를 확인하고 실행 결과를 보고해.
- 실제 운영 모델 변경은 별도로 요청하기 전까지 하지 말고, 교체·롤백 테스트는 격리 저장소에서 수행해.
- 합성 데이터의 기능 검증과 실제 데이터의 모델 성능 검증을 명확히 구분해.
- 원본 행 순서를 생산 시간순이라고 가정하지 마. 확인되지 않은 시간 관계로 시계열 성능을 주장하지 마.
- 비라벨 예측을 실제 정답으로 바꿔 재학습하지 마.

6. 작업 기록 및 다운로드 파일 제공
- 이번 작업에서 확인한 프로젝트 구조, 데이터 특징, 통계 용어, 설계 의도, 수정 내용과 검증 결과를 TXT로 정리해.
- 기존 요청은 2026-10-03 오후 12:30 이후의 작업 내역·모델링 검토 결과·사용자 프롬프트를 기록하는 것이었어.
- 기존 기록이 제공되면 보존하고 이번 작업 내역을 시간과 함께 추가해. 접근할 수 없는 과거 대화를 만들어내지 마.
- 학습한 내용은 확인한 사실·기술 설명·판단 근거로 정리하고, 자료로 확인하지 못한 가정은 별도 표시해.
- 소스·실행 명령·의존성·테스트 로그·결과·TXT를 다운로드 가능한 ZIP으로 제공해.
- 내가 요청한 작업을 전달할 통합 프롬프트와, 다른 AI가 모델링·워크플로우를 학습하고 검토할 인계 프롬프트도 제공해.
