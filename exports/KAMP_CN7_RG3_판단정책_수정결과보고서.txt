KAMP CN7·RG3 판단 정책 수정 및 테스트 결과
작성일: 2026-10-03

1. 사용자 요청
RG3는 불량 확정보다 정보 부족·위험 이력을 근거로 직접 재검사를 권고하고 구간을 표시한다.
CN7은 세 모델 가운데 실제 사용 기준을 만족하는 후보만 선정한다.

2. 코드 확인 및 수정
기존에는 구간별 표본 부족을 저장하지만 배치별 사용자 재검사 안내가 없었다.
CN7은 상대적 개선 조건이 있었으나 최소 탐지율·적중률 조건은 없었다.
decision_runtime.py를 추가하고 CLI와 운영 노트북에 연결했다.
기존 학습 모듈 pipeline_runtime.py는 보존하여 과거 실험을 그대로 재검산할 수 있다.

3. RG3 출력
배치별 inspection_advice.json/csv/txt 생성.
제품 기록 ID·패턴 fingerprint·확정 불가 상태·검사 권고·권고 근거 연결.
구간별 과거 위험 수/패턴 수·관측 비율·Wilson 구간·표본 부족 표시.
드리프트 판단도 함께 기록하되, 드리프트가 없다고 위험 이력 검사를 해제하지 않는다.
현재 배치 정답을 권고 생성에 사용하지 않으며 예측을 정답으로 바꾸지 않는다.
위험 이력이 있으면 직접 재검사, 정보 부족이면 추가 검사로 확인하도록 안내한다.
근거가 부족한 고/중/저 불량 확률은 제공하지 않는다.

4. CN7 선정
LR·RF·OCSVM 후보 각각 하나씩을 동일 평가 자료에서 비교하는 select-cn7 명령 추가.
잠정 기준: recall >= 0.5, precision >= 0.2, FPR <= 0.2.
이 값은 현장 승인이나 통계적 최적값이 아니므로 평가 전 검사 비용·허용 누락에 맞게 정해야 한다.
독립 평가·충분한 정상/위험 패턴·학습 중복 없음 조건도 필요하다.
모두 미달이면 selected=null, selection_held. 조건을 만족한 후보만 점수순으로 선정.
실제 운영 모델이 있으면 기존 대비 개선 조건도 적용한다.
자동 배포하지 않으며, 선택용 평가 점수를 독립 최종 성능으로 주장하지 않는다.

5. 실제 데이터 확인
RG3: 개발 자료의 위험 이력 구간을 기존 Test 119개 고유 패턴에 적용.
재검사 권고 119개/119개. 넓은 위험 이력 구간과 표본 부족 때문에 보수적으로 안내했다.
이는 정확도·불량률·검사 효율 입증이 아니다. 현재 정책은 검사량을 줄이지 못한다.
예시 JSON에서 각 패턴의 근거 구간을 확인할 수 있다.
CN7: 기존 LR Test 위험 3개 모두 누락, 최소 recall·precision 기준 미달로 보류.
이번 변경에서 세 모델을 새로 학습하거나 기존 Test를 보고 재선정하지 않았다.
CN7 기존 Test는 위험 3개로 최소 평가 위험 5개에도 미달하며 이미 관찰한 자료다.
운영 가능한 최종 모델 선정에는 별도 평가 근거가 필요하다.

6. 테스트
기존 운영 12개, 등록·LR 7개, OCSVM 24개, 새 판단 정책 6개: 총 49개 통과.
새 테스트: 낮은 절대 성능 차단, 표본 부족을 안전으로 표시하지 않음,
입력 라벨에 따른 권고 누수 방지, 배치 결과 파일 생성,
조건 통과 후보 선정/전원 미달 보류, 과거 평가 자료 승격 차단.
저장 LR 결과 재검산 통과. 실제 runtime 파일 해시 실행 전후 동일.
합성 데이터 테스트는 기능 검증이며 현장 성능 검증이 아니다.
