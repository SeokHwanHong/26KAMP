===================== 복사할 프롬프트 시작 =====================

너는 우리 KAMP 제조 데이터 분석 프로젝트의 코드 리뷰와 테스트 재현을 맡아줘.
먼저 현재 소스와 문서를 읽고 모델링 학습 흐름 및 전체 운영 워크플로우를 정확히 파악해.
그 후 실제 Python 코드로 테스트를 실행하고, 재현된 오류가 있으면 원인을 설명하고 수정·검증해.
머릿속 시뮬레이션이나 실행하지 않은 결과를 실제 결과처럼 말하지 마.

프로젝트 위치는 D:\workspace\kamp이고, 전달 ZIP을 쓰면 압축 해제한 KAMP 폴더가 루트야.
나는 통계 용어, 모델링 방향, 데이터 구조, 전체 아키텍처를 이해하고 싶어.
파이썬 문법 교육이나 부가 편의 기능보다 근거·학습·판단·검증 구조를 중심으로 설명해.

- 이미 존재하는 구현을 읽지 않고 새 파이프라인을 중복으로 만들지 마.

[2. 반드시 이해해야 할 데이터 계약]
- CN7·RG3 데이터, 모델, 버전은 각각 분리해.
- 모델 입력은 공정 변수 24개. ID·라벨·fold·패턴 메타데이터는 입력에서 제외해.
- 24개 입력이 정확히 같은 행을 한 패턴으로 집계해. 반올림이나 유사값 군집화가 아니야.
- 패턴 라벨은 max(PassOrFail). 한 번이라도 불량이면 위험 이력 패턴이야.
- 원본 ID, 제품 빈도, 정상/불량 관측 수, 원본-패턴 연결을 보존해.
- CN7: 원본1211행 → 606패턴, 정상592/위험14. 충돌11, 불량만3.
- RG3: 원본1182행 → 591패턴, 정상566/위험25. 위험25개 모두 정상과 공존.
- RG3 충돌을 모두 정상이라고 가정하면 위험 라벨이 0개라 불량 검증이 불가능해.
- 동일 입력의 상반된 라벨만으로 어느 행이 가짜인지 확정할 수 없어.
- 목표는 개별 제품 불량 확률이 아니라 위험 이력이 있는 패턴 탐지야.
- 생산 시간순은 확인되지 않았어. 파일 순서를 실제 시간이라고 가정하지 마.
- 비라벨 좌표계/스케일 정합은 미확인이야. 확인 전 자동 투입하지 마.
- 비라벨은 정합 확인 후 추론·감지만 하고, 예측을 실제 라벨로 바꿔 재학습하지 마.
- 학습은 고유 패턴, 운영 분포 감지는 제품 발생 빈도를 보존해야 해.

[3. 모델링 학습 흐름]
고정 개발/Test 분할 및 개발4-fold를 유지해.
CN7 개발484/Test122, RG3 개발472/Test119야.
IF와 OCSVM은 fold train 정상 패턴으로 학습하고, LR/RF는 정상·위험 전체로 학습해.
scaler·상수 제거·PCA 등은 train에서만 적합하고 검증/Test에는 저장 변환을 적용해.
IF 점수는 이상도와 검사 순위이며 불량 확률이 아니야.
IF→OCSVM은 필수 직렬 모델이 아니야. 기본 독립 학습, IF 정렬은 선택적 비교야.

로지스틱 회귀는 다음 조건을 확인해.
- raw_alltrain_scaled 기준: train 전체 상수 제거→train 전체 scaler→LR.
- 정상 기준 도메인 변환은 정상 train에만 적합하고 LR은 전체 train을 사용해.
- 8개 입력 구성, C=logspace(-4,3,15), 가중치 None/balanced.
- 1001개 숫자 임계값, 엄격한 probability > threshold 판정.
- 같은 후보의 모든 fold에 같은 임계값을 적용해.
- 합산 OOF F1 최대화, 동률은 fold F1 표준편차·입력 수·후보ID·임계값 규칙을 따라.
- 개발 전체 재학습 후 선택 임계값을 그대로 사용하고 Test에서 재조정하지 마.
- 계수는 인과 효과가 아니고 가중치가 있는 확률 출력을 보정된 제품 불량률로 해석하지 마.
- OOF 선택 점수는 독립 일반화 성능이 아니야.

[4. 최신 운영 워크플로우]
1 데이터 준비 → 2 EDA/패턴 전처리 → 3 초기 모델/분포 기준선
→ 4 신규 배치 전처리/저장 모델 추론 → 5 드리프트 감지
→ 6 원인·실제 라벨·자료량 확인 후 모델별 CT → 7 분리 평가/교체/롤백.

추론에서는 scaler를 재적합하지 않아.
배치 크기, 감지 윈도, 재학습 자료량은 다른 개념이야.
드리프트는 값별·구간별·조합별 비율과 같은 모델 버전의 점수/예측 변화를 비교해.
표본이 부족하면 누적 대기, 변화가 지속되면 원인 검토야.
변화 자체를 불량 확정이나 자동 재학습 명령으로 취급하지 마.
현재 경보선은 경험적 부트스트랩 기준으로 현장 시계열 특성까지 검증된 기준은 아니야.
IF/OCSVM/LR/RF의 CT는 전체 재학습으로 구현됐고 후보만 생성해.
기존 위험 이력을 신규 정상 기록으로 덮어쓰지 않도록 확인해.
학습·평가 패턴 중복, 비라벨 CT, 표본 부족 승격을 차단해야 해.
CD는 동일 평가 자료로 현재 모델과 후보를 비교하고, 통과한 해당 모델만 교체해.
기존 Test는 이미 관찰한 후속 평가라 운영 승격의 독립 근거로 쓰면 안 돼.

[5. RG3 분포 기반 구간 안내]
RG3는 위험 표본이 적고 같은 입력에 라벨이 충돌하므로 샘플링 한계를 고려해.
학습 자료에서 정한 고정 구간별로 다음을 안내해야 해.
- 참조·평가 고유 패턴 수
- 관측된 위험 이력 패턴 수와 비율
- 참고용 Wilson 95% 구간
- 참조 표본 부족과 평가 표본 부족을 각각 표시
- 미관측·위험0건 구간을 안전 구간으로 확정하지 않기
- 제공 좌표계의 구간이지 실제 온도/압력 물리 단위라는 보장이 없음을 표시
- 관측 위험 구간이지 불량 원인·필연적 발생 범위·제품 불량 확률이 아님을 표시
- 이 표를 보고 Test에 맞춰 모델이나 임계값을 다시 고르지 않기

추가로 다음을 소스와 실행으로 점검해.
1. 잘못된 스키마/NaN/무한값/ID중복/좌표미확인 입력이 보류되는가?
2. 빈도·원본 연결·최대라벨 집계가 일관되는가?
3. 윈도 중복 계산으로 지속 변화 횟수를 부풀리지 않는가?
4. 모델 버전 변경 전후 점수 분포를 잘못 비교하지 않는가?
5. 데이터가 계속 누적될 때 메모리·중복 배치·유효 패턴 부족을 처리할 수 있는가?
6. CT가 기존 위험 이력을 유지하고 평가용 자료를 배제하는가?
7. 동일 평가 자료로 비교하며 샘플 부족·오탐 초과·개선 없음이면 유지하는가?
8. 평가 후 모델/평가 파일 변경, 오래된 평가 결과, 운영 버전 변경을 감지하는가?
9. 해당 모델만 교체하고 이전 버전으로 롤백할 수 있는가?
10. 감사 당시 모델 해시와 현재 등록 파일, 설정, 분할, 코드가 일치하는가?
11. 실행마다 결과를 분리해 중간 실패와 과거 결과가 섞이지 않는가?
12. 노트북 기본 실행이 읽기 중심이고 재학습/교체를 몰래 수행하지 않는가?
