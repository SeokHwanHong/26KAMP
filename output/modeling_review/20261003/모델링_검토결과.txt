KAMP 최신 모델링 검토 결과 — 2026-10-03

대상
최신 7단계 아키텍처와 03.modeling의 IF·OCSVM·공통 저장 코드를 대조했다.
LR/RF는 최신 경로에서 매뉴얼 단계이므로 실행 모델 검증 대상으로 포함하지 않았다.
기존 modeling/의 관계식·스태킹 실험은 현재 주 모델의 결과와 구분했다.

결론
초기 실험 구조는 설계와 대체로 일치하며 실행한 기본 테스트는 통과했다.
다만 운영 적용을 승인할 근거는 부족하다. 후보 등록의 검증 연결과 실행 이력
보존을 보강해야 하며, 현재 모델 성능도 검사·운영 목적에 충분하다고 판단할 수 없다.

수정 권고 1 [P2]: 후보 등록 시 현재 모델과 검증 결과의 연결 확인 누락
위치: 03.modeling/common/00_pipeline_core.ipynb, register_ocsvm_baseline (셀 9)
현재 함수는 run_config의 dataset과 postrun_audit의 passed를 확인한다.
하지만 모델 해시를 verification.json의 감사 대상 해시와 대조하지 않으며,
현재 모델 threshold와 choice/선택 기록의 threshold 일치도 확인하지 않는다.
임시 복사본에서 감사 기록을 둔 뒤 모델 임계값만 +1000 변경했을 때도 후보
등록이 허용됐다. 실제 runtime 모델은 변경하지 않았다.
현재 실행 전체가 마지막 감사까지 성공하면 이 문제가 발생한다는 뜻은 아니다.
실행 중단·수동 파일 교체·등록 셀만 재실행하는 경우 오래된 통과 기록으로
다른 모델을 검증된 후보처럼 등록할 수 있다는 재현 결과다.
개선: 등록 시 현재 모델·선택 기록·입력·분할·코드 해시를 동일 실행 감사와
대조하고 불일치하면 거부한다. 모델과 choice의 임계값 일치도 확인한다.

수정 권고 2 [P2]: 고정 결과 경로로 실행 이력이 덮어써짐
위치: 03.modeling/models/ocsvm.ipynb, 실행 설정 셀 9
OUT이 output/pipeline/ocsvm/{dataset}/{training_order}로 고정돼 있다.
재실행하면 동일 이름의 run_config·탐색·선택·감사 결과를 덮어쓴다.
runtime 후보는 여러 버전으로 남지만 각 후보가 어느 실행의 전체 증거로
선택됐는지 추적하기 어려워진다. 중단된 실행의 신구 산출물이 섞일 수도 있다.
개선: 실행마다 고유 run_id 하위 폴더를 만들고 후보 manifest에 연결한다.
현재 결과 참조용 latest 포인터는 별도로 관리한다.

모델 성능 확인: 저장 모델을 다시 로드하여 현재 고정 Test에 추론
CN7 OCSVM: 위험 3개 중 0개 탐지, 정상 오탐 0개, F1 0.
RG3 OCSVM: 위험 5개 중 5개 탐지, 정상 오탐 89개, F1 0.101010.
RG3 정상 114개 중 89개를 경보 처리하므로 오탐률 78.07%다.
저장된 original/IF 정렬 비교 후보는 위 혼동행렬이 같다.
IF 고정 모델 상위 약 10% 검사:
  CN7 122개 중 13개 검사, 위험 3개 중 0개 탐지.
  RG3 119개 중 12개 검사, 위험 5개 중 2개 탐지.
IF와 OCSVM 표는 서로 다른 판단 정책이다. IF는 고정 검사량의 순위 평가,
OCSVM은 개발에서 선택한 임계값 평가이므로 직접 우열 비교에 사용하지 않는다.
기존 테스트를 재관찰한 소표본 결과이며 독립적인 운영 효과 검증이 아니다.

설계상 주의
1. OOF F1로 설정·임계값을 함께 고르는 구조이므로 그 OOF F1은 독립 성능이 아니다.
2. fold 정상 학습 후 개발 정상 전체로 다시 적합하면서 같은 수치 임계값을 사용한다.
   이는 현재 명시된 정책으로 코드 오류가 아니다. 단, 점수 분포가 달라질 가능성을
   별도로 검증해야 한다. Test를 보고 임계값을 다시 조정하면 안 된다.
3. RG3처럼 오탐이 많은 후보도 F1만 양수면 비교 후보로 저장된다. 현재 후보 저장은
   운영 승격이 아니며 active_ocsvm은 null이다. 운영 승격 시 검사량·오탐 허용 기준이 필요하다.
4. IF 정렬은 선택적 비교 기능이며 성능 향상이나 학습 가중치 증가를 보장하지 않는다.
5. 현 목표는 최대 라벨로 집계한 위험 이력 패턴이다. 개별 제품의 불량 확률이 아니다.

확인한 올바른 구조
CN7/RG3 분리, 고유 패턴 기준 분할, 정상 train만 IF/OCSVM 적합,
fold train 안에서 scaler/PCA/상수 제거 적합, 저장 변환으로 검증·Test 추론,
이상 점수 방향, score > threshold 판정, 합산 OOF 혼동행렬 계산,
Test 제외, 저장 모델 재로딩, 운영 포인터 자동 승격 없음.

검증 실행 범위
OCSVM 내장 테스트 6개를 CN7/RG3 × original/if_desc 4조건에서 실행: 총 24회 통과.
각 조건에서 소규모 1설정×4fold 탐색과 최종 적합 테스트를 수행했다.
실제 저장 IF의 정상 학습행·fold 분리 검증, OCSVM 후보 8개 재로딩·추론 확인.
원본 소스·runtime·기존 전처리 파일 해시가 작업 전후 동일한지 확인했다.
