KAMP CN7·RG3 드리프트 기반 지속 운영·재학습 파이프라인 — 구축 보고서
작성일: 2026-10-05 / 대상: develop_seo 작업 트리 / 검증: 전체 115개 테스트 + 저장 LR 감사 통과(21:23)

1. 개요
========================================================================
1.1 목적
 사출성형 공정 데이터(CN7·RG3)를 배치 단위로 받아, 저장된 모델로 판정하고, 분포 변화를 감시하며,
 변화의 원인이 확인되면 모델을 다시 학습해 검증된 경우에만 교체하는 '지속 운영 흐름'을 코드로 구축했다.
 이번 작업의 초점은 예측 성능 향상이 아니라, 자료가 중복·누락 없이 한 번만 처리되고, 장애가 나도
 같은 근거로 이어서 처리되며, 모든 판단의 근거 버전이 추적되는 것이다.

1.2 두 데이터를 다르게 다루는 이유
 개발 자료 교차검증(OOF)에서 단순 구간 위험 이력 점수가 위험 패턴을 무작위보다 잘 가려내는지 순열 검정으로 확인했다.
  - CN7: AUC 0.870, p=0.001 → 입력에 위험 신호가 있음 → '모델 판정' 정책(랜덤 포레스트 + 검사 예산)
  - RG3: AUC 0.451, p=0.776 → 무작위와 구분 안 됨 → '분포 감시' 정책(판단 불확실 정도와 추가 검사 안내)
 두 데이터는 같은 7단계 흐름을 공유하고, 5단계의 '결과를 만드는 방식'만 다르다.

1.3 범위
 포함: 배치 수집·추론·감지·안내·재학습·평가·교체·롤백, 장애 복구, 동시 실행 제어
 제외: 새 모델 탐색·성능 튜닝, 입력 변수 추가, 화면·DB·클라우드 구축, 현장 성능 검증

  - 사람이 확인해야 넘어가는 관문이 세 곳 있다: 좌표 정합 확인(4), 원인 확인(6), 승격 결정(7)
  - 비라벨 자료는 추론·감시에만 쓰고 재학습에 쓰지 않는다. 공정 이상을 새 정상으로 자동 흡수하지 않는다
  - 모든 단계의 출력에는 사용한 모델·기준선·정책 버전이 남는다

3. 정상 흐름 따라가기 — 배치 하나가 처리되는 과정
========================================================================
(예: CN7 라인에서 제품 300개가 담긴 배치 B가 들어온다고 가정)

3.1 [1단계] 데이터 준비 — "받아도 되는 자료인가"
 배치 B의 CSV에는 공정 입력 24개, 검사 결과(PassOrFail, 있을 때), 제품 ID가 있다.
 시스템은 먼저 24개 열·순서·수치형·결측을 확인하고, 운영자가 '좌표·스케일 정합 확인'과 라벨 출처를 명시했는지 본다.
 제품 ID는 데이터셋 안에서 고유한 생산 ID여야 한다(결측·빈 값·공백·실수형 거부).
 → 하나라도 맞지 않으면 배치를 '보류'로 기록하고 처리하지 않는다. 고친 뒤 같은 배치 ID로 다시 보내면 된다.
 ※ 대회 자료에는 생산 ID가 없어 ID 없는 예외 경로(내용 기반 중복 의심)로 처리된다.

3.2 [2단계] 전처리 — "제품 기록은 남기고, 학습 단위는 묶는다"
 같은 24개 입력을 가진 제품끼리 하나의 '패턴'으로 묶고, 그중 불량이 한 번이라도 있으면 위험 패턴으로 본다.
 이때 제품 300개의 원본 기록과 패턴별 제품 수·정상 수·불량 수는 그대로 남긴다.
 → 이후 단계는 두 단위를 구분해 쓴다: 검사 대상·분포 감시는 '제품', 학습·평가는 '패턴'.
 (초기 자료: CN7 1,211개 제품 → 606패턴, RG3 1,182개 → 591패턴)

3.3 [3단계] 초기 모델·기준선 — "무엇과 비교할 것인가" (최초 1회 + 교체 시)
 개발 자료로 모델(IF·OCSVM·LR·RF)을 학습해 각각 버전으로 저장하고, 운영 모델을 명시적으로 지정한다.
 기준선은 개발 패턴을 원본 제품 수만큼 복원한 '정상 운영 분포'와 운영 모델의 점수 분포다.
 → 배치 B는 이 기준선과 비교된다. 신규 배치는 기준선에 자동으로 편입되지 않는다.
 현재 CN7 운영: IF + 고정 설정 랜덤 포레스트(비교 기준 지정이며 최종 선정 모델이 아님)

3.4 [4단계] 배치 수집·추론 — "한 번만, 끝까지 기록하며 받는다"
 ① 중복 검사: 이전 배치와 제품 ID가 겹치면 보류, ID 없이 내용이 같으면 중복 의심 보류,
    ID는 새롭고 내용만 같으면 같은 조건의 새 생산으로 수집한다.
 ② 예약: 저장 전에 중복 색인에 먼저 기록한다(이후 어디서 멈춰도 같은 자료가 다른 ID로 들어오지 못함).
 ③ 추론: 저장된 전처리·모델로 점수를 낸다(학습 시 변환을 재적합하지 않음). 모델 버전을 함께 저장한다.
 ④ 확정: 장부에 등록하고, 처리 상태 파일에 '제품 ID-입력-라벨 연결 지문'을 남긴다.
 → 배치 B는 '수집 확정' 상태가 되어 감지 단계로 넘어간다.

3.5 [5단계] 드리프트 감지 + 결과 — "분포가 달라졌는가, 그래서 무엇을 할 것인가"
 감지는 배치 하나가 아니라 아직 감지에 쓰지 않은 배치를 누적한 '윈도' 단위로 한다.
  - 제품 200개·고유 패턴 40개가 모이기 전까지는 '판단 대기(waiting)'
  - 모이면 입력 24개·변수 조합·모델 점수의 구간 비율을 기준선과 비교해 TV 거리(0~1)를 구하고,
    참조 자료를 200회 재표집해 만든 경보선(99% 지점)과 비교한다
  - 경보선 초과 1회 → 관찰(watch), 같은 기준선·정책에서 2회 연속 → 원인 검토(review), 초과 없음 → 정상(normal)
 그리고 데이터별 결과를 만든다.
  - CN7: 운영 RF 점수로 배치 안 제품 순위를 매기고, 검사 비율(기본 10%)만큼 정확히 k개를 검사 대상으로 표시한다.
  - RG3: 제품마다 '학습 범위 밖 / 정보 부족 / 위험 이력 참고 / 관찰' 근거와, 분포 상태를 합친 판단 불확실 단계
    (높음·중간·판단 대기·낮음)를 안내한다.
 → 평상시에는 여기서 결과를 제공하고 다음 배치를 기다린다. review가 나오면 6단계 검토가 열린다.
 ※ 결과 안내에는 사용한 모델·기준선·경보 정책이 고정 기록된다.

3.6 [6단계] 모델별 재학습 — "확인된 변화만, 확정된 라벨로"
 review가 나왔다고 자동으로 재학습하지 않는다. 운영자가 원인을 확인해 기록하고,
 해당 윈도의 라벨 배치가 있고, 고유 정상 30개(지도학습은 위험 5개도) 이상일 때만 후보를 만든다.
 기존 학습 자료에 새 라벨 패턴을 합쳐 같은 입력은 최대 라벨로 통합한다(과거 위험 이력을 지우지 않음).
  - IF·OCSVM: 확인된 정상 패턴만 / LR·RF: 정상·위험 전체로 다시 학습
  - 임계값은 기존 모델 것을 유지하고, 결과는 '후보'로만 저장한다.

3.7 [7단계] 검증·교체 — "같은 시험지로 비교하고, 통과한 것만 바꾼다"
 학습에 쓰지 않은 실제 라벨 평가 자료를 등록한다(이미 본 Test는 승격 근거로 쓰지 않음).
 후보와 현재 모델을 같은 자료로 비교한다.
  - CN7: 같은 검사량(exact_k)에서 찾아낸 위험 이력 패턴 수로 비교. 예산 내 최대치의 50% 이상이고 현재 모델보다 많아야 통과
  - 모델 고르기에 쓴 평가 자료(겹치는 패턴 포함)로는 승격할 수 없다
 통과하면 새 모델의 점수 기준선을 먼저 만든 뒤 운영 모델·기준선을 함께 교체하고, 이전 버전은 보존한다.
 → 이후 배치는 새 모델·기준선으로 다시 4단계부터 처리된다. 문제가 있으면 롤백으로 되돌린다.

 | 다시 들어온 자료                         | 처리                                        |
 | 완전히 같음 / 행 순서만 다름             | 이미 완료면 '완료됨' 응답, 미완료면 남은 단계 재개 |
 | 제품 ID 교체, ID끼리 입력 맞바꿈          | conflict(원본 유지)                          |

4.3 동시에 여러 작업이 실행되는 경우
 수집·감지·평가·교체는 공통 운영 잠금을 먼저 잡아 한 번에 하나만 실행된다(잠금 순서 고정으로 교착 방지).
 작업이 비정상 종료해 잠금이 남으면, 작업 종료를 확인한 뒤 사유를 남기고 해제한다.

5. 결과 해석
========================================================================
 - CN7 검사 순위: "위험 이력 패턴과 비슷한 순서"이지 불량 확률이 아니다. 검사량은 제품 수 기준,
   평가의 발견 수는 고유 패턴 기준이라 같은 10%라도 뜻이 다를 수 있다.
 - RG3 안내: 높음·중간·판단 대기·낮음은 '판단할 근거가 얼마나 부족한가'이지 불량 위험도가 아니다.
   구간 위험 이력(Wilson 95% 구간)은 참고 정보이며 예측력이 검증되지 않았다.
 - 감지 상태: normal은 '경보 없음'이지 품질 정상 보증이 아니고, review는 '원인 검토 신호'이지 불량 확정이 아니다.
 - 연속 경보는 배치 도착 순서 기준이다(실제 생산 시간순은 미확인).

6. 검증 결과
========================================================================
 - 전체 115개 테스트 통과: 운영 12 + 등록/LR 8 + OCSVM 24 + 판단·복구·재전송 58 + 운영 계층 13
   (재전송 판단은 ID 출처·재전송 유형·처리 단계·기록 손상 상태를 교차한 226개 하위 조합으로 검증)
 - 격리 종단 리허설(CN7·RG3): 초기 기준 → 라벨 배치 → 관찰/원인 검토 → 원인 확인 → 재학습 후보 →
   평가 보류·유지 → 통과 후보 평가 → 승격 → 롤백, 비라벨 추론 포함
 - LR 저장 결과 감사: 240개 설정 기록 재집계, 선택 재현, Test 예측 재현, 선택 설정 재학습 재현(과거 240개 전부 재학습은 아님)
 - 실제 운영 폴더와 기존 LR 결과는 검사 전후 해시 동일
 - 과정: 팀장 검토 2회(지적 F01~F07, R01~R03 및 정적 지적) 반영, Claude·Codex 교차 검수에서 추가 결함 11건 보완

7. 한계와 다음 단계
========================================================================
 한계
 - 테스트는 합성 자료로 기능·장애 복구를 확인한 것이며 현장 정확도나 최적 모델 입증이 아니다
 - 대회 자료에는 생산 ID·생산 시각이 없어 재전송과 '같은 조건의 새 생산'을 완벽히 구분하지 못한다
 - CN7 RF는 비교 기준으로 지정한 것이며, 기존 Test는 여러 번 관찰돼 독립 평가가 아니다
 다음 단계
 1) 현장 조건 합의: 검사 비율, 누락 허용량, 좌표·스케일 정합
 2) 독립 라벨 평가 자료 확보(위험 5개 이상) → CN7 모델 최종 판단
 3) RG3 생산 순서·라벨 의미 확인
