[결론]
프롬프트대로 구조 파악, 테스트 실행, 문제 재현·수정 검증까지 마쳤다.
- run_checks.py 4종 중 운영 12개, OCSVM 24회는 통과했다.
- 나머지 2종은 실패했다. 원인은 실행 환경과의 버전 차이(소수점 아래 16자리 수준)이며 판정 결과는 같다.
- 별도로, 같은 배치를 다시 보내면 재학습(CT)까지 잘못 열리는 결함을 하나 찾았다.

원본 소스·데이터·분할·runtime은 바꾸지 않았다(작업 전후 해시 확인).

[실행 환경의 한계]
- 사용자 PC가 아니라 Claude 클라우드에서 실행했다. 연결된 기기에 직접 실행 도구가 없어서다.
- 환경: Python 3.11 / scikit-learn 1.8.0
  프로젝트 기준: Python 3.14 / scikit-learn 1.9.0
  패키지 설치가 막혀 버전을 맞출 수 없었다.
- 운영 코드가 IPython을 불러오는데 이 환경에 없었다.
  처음 실행에서는 4개 스크립트가 모두 이 import에서 실패했다.
  프로젝트 밖 임시 폴더에 빈 대체 모듈만 두고 진행했다.

[run_checks.py 결과 (원본 코드)]
- test_operations.py: 12/12 통과
- test_existing_ocsvm.py: 24/24 통과
- test_registration_and_logistic.py: 6/7 통과, 1개 실패
- audit_logistic_runs.py: 실패

두 실패의 원인
- 저장된 확률을 비트 단위로 비교해서 생겼다.
- 차이는 4×10^-16이고, 위험/정상 판정은 완전히 같다.

보조 재검산
- 허용오차를 둔 재검산은 두 데이터셋 모두 통과했다.
- 확인 항목: 240,240행 재집계, 선택 후보 재현, fold 분리, OOF 각 1회.

LR 독립 재실행
- LR 전체 탐색을 새로 돌려 봤더니 선택 결과와 Test 혼동행렬이 Codex 실행과 같았다.

[발견한 문제]
P2 — 같은 배치를 다시 보내면 재학습까지 열린다
- 같은 CSV를 배치 ID만 바꿔 두 번 넣으면 2회 연속 변화로 집계된다.
  그 결과 원인 검토(review) 상태가 되고, 재학습 후보까지 만들어진다. 실제로 재현했다.
- 수정안: 내용이나 제품 ID가 이전 배치와 겹치면 보류하는 코드와 회귀 테스트.
- 검증
  - 새 테스트는 원본 코드에서 실패하고 패치 코드에서 통과한다.
  - 패치 적용 후 run_checks 4개 스크립트 모두 통과했다.
- 적용 여부
  - duplicate_batch_fix.patch로만 저장했고 원본 소스에는 적용하지 않았다.
  - 적용하면 아래 첫 번째 P3 때문에 LR 감사가 실패해서, LR 재실행이 필요하기 때문이다.

P3 (7건)
1. 운영 코드만 고쳐도 LR 감사가 실패한다.
   LR 실행 기록이 운영 코드 파일 전체의 해시를 고정하기 때문이다.
2. 확률을 비트 단위로 비교해서, 팀원 PC 환경마다 테스트가 깨질 수 있다.
3. 최신 실행 폴더를 이름순으로 골라서, 중단된 실행 폴더가 있으면 감사가 오류로 끝난다.
4. 테스트 산출물이 실행별 폴더가 아니라 고정 폴더에 덮어써진다.
5. LR 노트북에 .py 코드가 통째로 복사돼 있어, 둘이 어긋나도 확인하는 장치가 없다.
6. 잠금 파일이 남으면 직접 지우기 전까지 모든 쓰기 명령이 멈춘다.
7. 운영 코드가 IPython에 의존하는데 requirements에 직접 적혀 있지 않다.

[모델 해석]
CN7 LR
- Test 위험 3건을 모두 놓쳤지만 AUC는 0.91이다.
- 순위는 맞는데, 개발 OOF로 고른 임계값 0.921을 아무도 넘지 못한 것이다.

RG3 LR
- 사실상 전부 위험으로 판정한다(Test 오탐률 96%).
- F1 0.083은 "항상 위험"이라고 답할 때(0.081)와 거의 같고, AUC는 0.38이다.
- "재현율 100%"를 성과로 인용하면 안 된다.

RG3 구간 안내
- 표본 부족 표시와 "0건 ≠ 안전" 처리는 적절하다.
- 다만 "평균보다 높음" 표시가 23개 구간에 붙었는데,
  신뢰구간 하한까지 평균을 넘는 구간은 5개뿐이다.
