1. 이해한 전체 아키텍처와 학습 흐름
======================================================================
[데이터 계약]
- CN7·RG3는 데이터·모델·버전·runtime 폴더를 완전히 분리한다.
- 입력은 공정 변수 24개(data/schema/input_features.json, 열 순서까지 강제). ID·라벨·fold 제외.
- 24개 값이 정확히 같은 행을 한 패턴으로 묶고 라벨 = max(PassOrFail) = "위험 이력 패턴".
  CN7 1,211행→606패턴(정상592/위험14, 충돌11·불량만3), RG3 1,182행→591패턴(566/25, 전부 충돌).
- 고정 분할: Test 20% + 개발 4-fold. CN7 개발484/Test122, RG3 개발472/Test119.

[초기 학습 단계 — 03.modeling/models]
- IF(04.1): fold train 정상으로 학습, 점수 = 이상도·검사 순위(불량 확률 아님). 최종 IF는 고정 버전.
- OCSVM(ocsvm.ipynb): 정상 train만 적합, 7시나리오×616설정×93임계값, 합산 OOF F1 선택.
  기본 TRAIN_ORDER='original'(IF와 독립), 'if_desc'는 선택적 비교 모드.
- LR(logistic_regression.py): 8입력구성 × C=logspace(-4,3,15) × 가중치{None,balanced} = 240설정,
  임계값 1,001개, 판정 p > t, 같은 후보의 모든 fold에 같은 t. 합산 OOF F1 → 동률 시
  fold F1 표준편차·입력 수·후보ID·임계값 규칙. 개발 전체 재학습 후 같은 t로 Test 후속 평가.
  raw_alltrain_scaled는 train 전체로 상수제거·scaler 적합. 도메인 구성은 정상 train에만 도메인 변환을
  적합하고 LR은 train 전체로 학습(테스트로 확인: 도메인 scaler 표본=정상 수, 최종 scaler=개발 전체).
- RF: 운영 공통에 고정 기준 모델(max_depth5 등)과 전체 재학습만 있고, 매뉴얼 전체 탐색은 미실행.

[운영 단계 — common/pipeline_runtime.py, pipeline_cli.py, 04_operations.ipynb]
1 데이터 준비 → 2 패턴 전처리(preprocess: 지문=24값 sha256, 제품 빈도·원본 ID 보존)
→ 3 초기 모델·기준선(create_baseline: 개발 패턴을 제품 빈도만큼 복원, Test 제외)
→ 4 배치 추론(ingest: 좌표 정합 선언 없으면 보류, 저장 변환 사용·재적합 없음)
→ 5 드리프트(detect: 값별/분위 구간/2변수 조합/같은 버전 점수·예측 비율의 TV 거리,
   제품≥200·고유패턴≥40 누적 대기, 참조 부트스트랩 99% 분위 = 시험 경보선, 2회 연속 → review)
→ 6 CT(retrain: review 상태·원인 기록·라벨 배치 필수, 기존 corpus+신규를 max 라벨로 재집계,
   Test·등록 평가 패턴 차단, IF/OCSVM은 정상만, LR/RF는 전체로 "전체 재학습", 후보만 생성)
→ 7 CD(evaluate: 동일 평가 자료로 현재·후보 비교, 정상≥30·위험≥5, 분류는 F1 개선+Recall 유지+FPR≤0.2,
   IF는 동일 검사량 기대 탐지 수 증가 / promote: 해시 재확인 후 해당 모델만 교체, rollback 지원)
- 비라벨은 정합 확인 후 추론·감지만, 재학습 제외. 의사 라벨(pseudo-label) 경로 없음.
