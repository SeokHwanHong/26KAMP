0. 보고서 첫머리에 쓸 내용
========================================================================
0.1 한 줄 요약
 10/3까지 만든 '학습 단계(1~3)' 위에, 새 생산 배치를 받아 판정·감시·재학습·검증·교체가 반복되는
 '운영 단계(4~7)'를 구축했고, 실제 운영에서 생길 수 있는 사고(중복·중단·버전 혼선·동시 실행·교체 실패)에
 대비한 장치를 더했다. 기능 검증은 자동 테스트 122개 + LR 감사 통과로 확인했다.

0.2 목적
 예측 성능 향상이 아니라, 자료가 중복·누락 없이 한 번만 처리되고, 장애가 나도 같은 근거로 이어서 처리되며,
 모든 판단의 근거 버전이 추적되는 운영 흐름을 만드는 것.

0.3 두 데이터를 다르게 다루는 이유 (단계 5·7의 근거)
 - 개발 OOF 순열 검정: CN7 AUC 0.870(p=0.001) → 모델 판정(RF + 검사 예산)
 - RG3 AUC 0.451(p=0.776) → 분포 감시(판단 불확실 단계 + 추가 검사 안내)
 - 같은 7단계 흐름을 공유하고 5단계의 결과 생성 방식만 다르다.

0.4 진행 경과 (부록으로 둬도 됨)
 팀장 검토 1차(F01~F07) → Claude 수정·Codex 검수 2회 → 팀장 검토 2차(R01~R03 + 정적 지적) →

1단계. 데이터 준비 — "받아도 되는 자료인가"
========================================================================
[목적] 판정에 쓸 수 없는 자료가 운영에 섞이지 않게 입구에서 거른다.
[입력]
 - CN7·RG3 분리. 공정 입력 24개(스키마 파일 기준), 선택적으로 합격/불합격 라벨(PassOrFail), 제품 ID(record_id/product_id)
 - 운영자의 명시 선언: 좌표·스케일 정합 확인(--coordinates-confirmed), 라벨 출처(--label-source)
[처리·검사]
 - 24개 열·순서·수치형·결측/무한값 확인. 라벨은 0/1만, 라벨이 있으면 출처 필수
 - 좌표 정합 확인이 없으면 추론·감지 보류(열 이름이 같다는 것만으로 정합을 판단하지 않음)
 - 제품 ID 계약(사용자 결정)
   A(기본): 제품 ID = 데이터셋 안에서 고유한 생산 ID. 문자열·정수만, 결측·빈 값·앞뒤 공백·실수형·배치 내 중복은 보류
   C(예외): ID 열이 없으면 내부 번호를 쓰되 배치 간 비교에 쓰지 않음. 'Unnamed: 0'은 파일 행 번호이지 ID가 아님
[재검사·재처리] 보류 배치는 저장된 것이 없으므로 고쳐서 같은 배치 ID로 다시 보냄(이전 시도는 보관 폴더로 이동)
[산출물] 보류 사유가 담긴 배치 manifest(status=held)
[이번 변경] 제품 ID 계약 도입(R02 대응), ID 값 검증(Codex 검수 지적)
[검증 근거] A 계약 ID 결측·빈 값·공백·실수형·혼합 자료형 거부 테스트
[한계] 대회 원본 자료에는 생산 ID·생산 시각이 없어 현재 자료는 모두 C 경로

2단계. EDA·전처리 — "제품 기록은 남기고, 학습 단위는 묶는다"
========================================================================
[목적] 같은 조건의 반복 생산을 하나의 학습 단위로 묶되, 실제 생산 빈도와 원본 기록은 보존한다.
[입력] 초기 학습 자료(moldset_labeled/unlabeled), 운영 배치(1단계 통과분)
[처리·검사]
 - 24개 입력이 완전히 같은 제품을 하나의 패턴으로 통합(반올림·대체·삭제 없음)
 - 패턴 라벨 = 원본 라벨 최댓값(불량 이력이 한 번이라도 있으면 위험)
 - 제품 단위 기록(products)과 패턴 단위 기록(patterns: 제품 수·정상 수·불량 수) 분리 보존
 - 비라벨은 라벨을 만들지 않고 별도 보관, 학습 제외
 - 도메인 파생변수는 이 단계에서 만들지 않음(모델링 fold train에서 적합)
 - 초기 결과: CN7 1,211 → 606패턴(정상 592/위험 14), RG3 1,182 → 591패턴(566/25, 위험 전부 정상·불량 공존)
[재검사] 저장 후 다시 읽어 값 일치, 원본 행 ↔ 패턴 연결로 원본 입력 복원 검증, 해시 기록
[산출물] data/processed/<ds>/conservative/(X·y·메타데이터·원본 연결표·manifest·validation)
[이번 변경] 없음(전처리 정책 유지가 팀장 검토 전제). 운영 배치에서 같은 정책이 적용되는지만 확인
[한계] 예측 목표는 '개별 제품 불량'이 아니라 '불량 이력이 있는 입력 조건'

3단계. 초기 모델·기준선 — "무엇과 비교할 것인가"
========================================================================
[목적] 운영에서 쓸 모델과, 이후 모든 판단의 비교 기준(기준선)을 정한다.
[입력] 고정 분할: Test 20%(패턴 단위 고정) + 개발 4-fold. Test는 여러 번 관찰돼 '후속 평가'로만 취급
[처리]
 - IF·OCSVM: 정상 패턴 기준 / LR: 240개 설정 × 임계값 1,001개를 OOF로 선택 / RF: 고정 설정(나무 300·깊이 5·잎 최소 5·불균형 보정)
 - 모델마다 독립 버전 저장(모델 해시·스키마·라이브러리 버전·학습 패턴 지문). 후보 저장과 운영 지정은 별도 명령
 - 기준선: 개발 패턴을 원본 제품 수만큼 복원한 입력 분포 + 운영 모델 점수 분포.
   구간 정의는 값 12종 이하 → 값별, 그 외 → 10분위. 신규 배치는 자동 편입하지 않음
[검사]
 - 학습 패턴에 Test·평가 패턴이 섞이면 저장 거부, 모델 로드 시 해시·버전 불일치 거부
 - baseline-status(읽기 전용): 기준선 파일 해시·모델 버전·운영 모델 일치 확인
[재검사]
 - LR 감사: 240,240개 설정 기록 재집계, 선택 재현, Test 예측 재현, 선택 설정을 현재 코드로 재학습해 저장 모델과 비교
   코드 출처는 provenance 보관본(수정 전 pipeline_runtime)으로 확인, 노트북 학습 코드는 2026-10-05 스냅샷으로 변경 감시
[현재 운영 상태]
 - CN7: IF + RF(rf-20261005T070541Z-eee06bbc), 기준선 baseline-20261005T070541Z-8461282d, 유효
 - RG3: IF만 지정, 기준선 없음 → 검사 실행기가 '운영 준비 미완료'로 실패 판정(종료 코드 1)
[이번 변경] CN7 RF 운영 기준 지정, 기준선 유효성 읽기 전용 확인, LR 감사 출처 보존 방식(팀장 2차·Codex 검수 대응)
[한계] RF 지정은 비교 기준 지정이며 최적 모델 선정이 아님. LR 감사는 선택 설정 재학습이지 240개 전체 재학습이 아님
[결정 필요] RG3 기준선 준비(초기 미준비인지 확인 후 baseline 생성 여부)

4단계. 배치 유입·추론 — "한 번만, 끝까지 기록하며 받는다"
========================================================================
[목적] 새 생산 배치를 중복 없이 한 번만 받아 저장된 모델로 판정하고, 처리 단계를 추적한다.
[입력] 1·2단계를 통과한 배치
[처리 순서] (공통 운영 잠금 안에서 한 번에 하나만)
 1 모델 전환 미완료면 거부, 현재 기준선 검증
 2 중복 검사: 제품 ID 겹침 → 보류 / ID 없이 내용 같음 → 중복 의심 보류 / ID 새롭고 내용만 같음 → 새 생산으로 수집
 3 저장 전 중복 색인에 예약(이후 어디서 멈춰도 같은 자료가 다른 ID로 못 들어옴)
 4 저장 모델로 추론(변환 재적합 없음), 제품·패턴·예측과 모델 버전 저장
 5 장부 등록 → 처리 상태 기록(제품 ID-입력-라벨 연결 지문, ID 계약) → 예약 정리
[재검사·재처리]
 - 같은 배치 ID 재전송: 저장 제품 파일(해시 검증)에서 연결 지문을 다시 계산해 비교
   같은 자료/행 순서만 다름 → 완료면 already_completed, 미완료면 남은 단계 재개
   ID 교체·ID별 입력 맞바꿈·라벨 변경·ID 열 추가/제거 → conflict(원본 유지)
   검증 불가(좌표 미확인·입력 오류) → rejected
   manifest·제품 파일 누락/손상인데 수집 이력 있음 → rejected(재수집 금지)
   ID 계약 근거 손상 → C로 추정하지 않고 rejected
 - resume(자료 없이 재개)도 완료 응답 전에 저장 파일 목록·해시·ID 계약·연결 지문을 검증, 손상 시 rejected
 - 중단 상태: reserved_not_stored / commit_incomplete → 같은 ID 재전송 또는 resume
 - 라벨 정정은 재전송으로 처리하지 않음(정정 절차 요구사항만 문서화)
[산출물] batches/<ID>/(products, patterns, predictions, manifest, processing), batch_ledger.json, dedup_index.json
[이번 변경] F01(행 순서 재전송), F02(단계 분리·재개), F03(잠금), R02(연결 지문), 수집 확정 도중 실패 복구,
           증거 손상 처리, resume 무결성 검증(Codex 재검토)
[검증 근거] 재전송 조합 테스트 226개 하위 조합(ID 출처 4 × 재전송 유형 × 처리 단계 × 기록 손상·라벨 상태),
           응답뿐 아니라 장부 횟수·파일·예약 불변까지 확인 / resume 무결성 20조합
[한계] ID 없는 자료(현재 대회 자료)는 재전송과 같은 조건의 새 생산을 내용으로만 구분(중복 의심 보류)

5단계. 드리프트 감지 + 데이터별 결과 — "분포가 달라졌는가, 무엇을 할 것인가"
========================================================================
[목적] 학습 당시와 공정 분포가 달라졌는지 감시하고, 데이터별로 검사 판단을 돕는 결과를 낸다.
[입력] 아직 감지에 쓰지 않은 accepted 배치 누적(배치와 감지 윈도 분리)
[처리·검사]
 - 제품 200개·고유 패턴 40개 미만 → waiting(판단 대기)
 - 입력 24개 값 + 변수 조합 2개 + 모델 점수·예측을 기준선 구간으로 범주화 → 표현별 TV 거리(0~1)
 - 경보선: n_eff = min(참조 제품 수, 현재 고유 패턴 수)로 참조를 200회 재표집, 회차별 최대 TV의 99% 지점
 - 초과 1회 watch, 같은 기준선·같은 경보 정책에서 2회 연속 review, 초과 없음 normal
[데이터별 결과]
 - CN7: 운영 RF 점수로 제품 순위 → exact_k(검사 비율 기본 10%, 0% 불가, 최소 1개), 동점은 입력 지문 → 제품 ID 순
 - RG3: 제품별 근거(학습 범위 밖/정보 부족/위험 이력 참고/관찰) + 판단 불확실 단계(높음/중간/판단 대기/낮음),
   구간 위험 이력은 Wilson 95% 구간(참조 20패턴·위험 5개 미만은 표본 부족)
[재검사·재처리]
 - 감지 결과 저장 후 소비 장부 실패 → 다음 감지·재개 때 감지 ID 기준 1회 반영(재소비 없음)
 - 경보 정책 변경 → 경보선 캐시 보관 후 재계산, 연속 횟수 새로 셈
 - 안내 실패 후 재개 → 최초 기록한 모델·기준선·정책 그대로 사용(advice_context), 근거가 없거나 바뀌면 명시적 실패
 - waiting 배치가 후속 윈도에 포함 → 배치↔감지 연결 갱신, 새 안내 revision, 최초 안내 이력 보존(재수집·재소비 없음)
 - 후속 안내 실패 → refresh-advice로 재개 / batch-status로 '처리 완료'와 '분포 판단 확정'을 따로 조회
[산출물] drift/, monitor.json, batch_drift_links.json, inspection_priority.*(CN7), inspection_advice.*(RG3),
        advice_history/<revision>, advice_latest.json
[이번 변경] F04(판단 대기), F05(동점 규칙), F06(경보선 캐시), R01(감지 소비 장부 복구), P1-1(버전 고정),
           P1-2(후속 연결), advice_context 보존(Codex 재검토)
[검증 근거] 감지 장애 4지점·재개 반복 멱등성, 정책별 연속 횟수, CN7/RG3 안내 실패 → 모델 교체 → 재개 시나리오
[해석 주의] normal은 경보 없음(품질 보증 아님), review는 원인 검토 신호(불량 확정·자동 재학습 아님),
           CN7 점수는 순위이지 불량 확률 아님, RG3 단계는 판단 근거 부족 정도이지 위험도 아님,
           연속 경보는 배치 도착 순서 기준(생산 시간순 미확인)

6단계. 모델별 CT(재학습) — "확인된 변화만, 확정된 라벨로"
========================================================================
[목적] 지속 변화가 확인되고 원인이 밝혀진 경우에만 새 라벨로 후보 모델을 만든다.
[입력] review 감지 ID, 원인 기록, 해당 윈도의 라벨 배치
[처리·검사]
 - 기존 학습 자료 + 새 라벨 패턴을 합쳐 같은 입력은 최대 라벨로 통합(과거 위험 이력을 새 정상으로 덮어쓰지 않음)
 - 조건: review 이후, 원인 기록 필수, 현재 운영 모델 기준, 감지 이후 모델이 바뀌었으면 새 기준선에서 감지부터 다시
 - 비라벨 배치 제외, Test·평가 패턴 섞이면 거부, 고유 정상 30개 이상(LR·RF는 위험 5개 이상도)
 - IF·OCSVM: 확인된 정상만 / LR·RF: 정상·위험 전체로 전체 재학습(부분 학습 아님), 임계값은 부모 모델 유지
 - 결과는 후보로만 저장, 자동 운영 지정 없음
[재검사] 후보에 원천 감지 ID·배치·원인·기존/신규 패턴 수 기록 → 7단계에서 판단
[이번 변경] 운영 잠금·전환 미완료 차단 적용(P1-3), 그 외 로직 유지
[검증 근거] 4종 모델 CT 통합 테스트, 종단 리허설의 LR 후보 경로
[한계] 종단 리허설은 LR 후보 경로로 실행(모든 모델 조합의 종단 검증은 아님)

========================================================================
7단계. 검증·교체 — "같은 시험지로 비교하고, 통과한 것만 바꾼다"
========================================================================
[목적] 후보가 현재 모델보다 나은지 분리된 평가 자료로 확인하고, 통과한 경우만 일관되게 교체한다.
[입력 — 평가 자료 등록]
 - 실제 라벨 평가 자료. 목적 independent(승격 근거 가능) / historical_followup(근거 불가)
 - 학습 이력 패턴은 독립 평가로 등록 거부, 기존 Test 패턴이 있으면 historical_followup 강제
 - CSV에서 입력 지문 재계산 → 저장 열·manifest 대조, 라벨 0/1 확인, manifest 해시 고정
 - 같은 내용을 새 ID로 재등록하면 이전 평가 ID와 연결(독립성이 새로 생기지 않음)
[처리·검사 — 평가]
 - 평가·승격 직전 모두 기록·목적·자료 해시 재확인, 평가 정상 30·위험 5 미만이면 보류
 - CN7(검사 예산): 같은 자료·같은 검사량(exact_k)에서 위험 이력 패턴 발견 수(found_TP) 비교.
   예산 내 최대 발견 가능 수의 50% 이상 + 현재 모델보다 많아야 통과. all_ties는 참고 전용(선정·승격 불가)
 - 모델 선정(select-cn7)에 쓴 자료(겹치는 패턴 포함)로는 승격 불가
 - threshold 모드: F1 개선 + 재현율 유지 + 오탐률 0.2 이하 / IF: 같은 검사량 발견 기대 수 개선
[교체]
 - 새 모델 출력 기준선을 먼저 준비(입력 참조는 개발 분포 유지) → 레지스트리·기준선 포인터를 함께 전환
 - 전환 기록: preparing → prepared → completed, 이전 버전 보존
[재검사·재처리]
 - 기준선 준비·포인터 기록 중 실패 → 전환 미완료 상태에서 추론·감지·CT·평가 차단, resume-transition으로 같은 전환 재개
 - 롤백도 같은 전환 절차(사유 필수)
 - 평가 후 모델·자료·운영 모델이 바뀌었으면 승격 거부(재평가)
[이번 변경] F07(평가 목적 해시), R03(선정·승격은 exact_k), P1-4(전환 복구), P2-1(평가 지문 재계산·재등록 이력·선정 자료 겹침 차단)
[검증 근거] 기준선 준비 실패·포인터 저장 실패·롤백 실패 후 복구 테스트, 평가 지문 변조·재등록·부분 겹침 차단 테스트
[한계] 실제 운영 모델 승격·롤백은 수행하지 않음(격리 합성 자료로만 검증)

공통 — 동시 실행·상태 기록·검사 실행
========================================================================
