# RF 논리·통계 검토 PDF와 현재 코드 대조

검토일: 2026-10-06  
대상 문서: `KAMP_RF_논리통계_검토정리_20261006.pdf` 4쪽 전체  
대상: RF 실험 코드, 공통 학습 runtime, 현재 CN7 운영 모델 및 문서

## 판단

정상 참조집단 → 재표준화 → PCA → 같은 공간의 재구성 잔차라는 **핵심 계산은 현재 RF 실험 코드와 일치**한다. 이 PDF를 근거로 7단계 운영 파이프라인 전체를 다시 구축할 필요는 없다.

다만 보고서의 설명을 보완하고, 작은 분산의 처리 정책을 명시하며, **실험 RF의 변환 계약과 운영 runtime의 변환 계약을 구분**할 필요가 있다. 실험 경로를 운영에 연결할 때는 마지막 항목이 코드 수정 대상이 된다.

## 문서 주장과 구현 대응

| 검토 항목 | 확인한 현재 구현 | 판단 |
|---|---|---|
| 정상 참조집단 | `Xtrain` 안에서 `ytrain == 0`인 고유 패턴 선택 | 일치. 불량 이력이 없는 관측 패턴이라는 설명 필요 |
| 계산 단위 | `StandardScaler.fit(normal)`에 빈도 가중치 없음 | 정상 고유 패턴마다 동일 가중치. 제품 빈도 분포라는 설명은 부적절 |
| fold 내부 적합 | 각 fold의 train에서 변환 적합 후 validation에 transform | 정적 검토 및 8개 실제 fold 변환 확인 |
| 정상 기준 PCA | 정상 z 좌표에 공정군별 PCA 적합 | 일치 |
| 성분 수 | `min(2, 활성 센서 수)`, full SVD, whitening 기본 false | 고정 표현 크기이며 최적 성분 수 입증은 아님 |
| RMSE 공간 | z 입력과 PCA inverse_transform 복원값의 차이 | 일치. 물리 단위 오차·불량 확률로 표현하지 않음 |
| 전치·평균 복원 | `inverse_transform(scores)` 사용 | 코드 계산 정상. 첨부 PDF 3쪽 수식도 정확하게 표기됨 |
| 신규 입력 변환 | 저장 scaler/PCA/variance의 transform 사용 | 제한 검증에서 변환 상태 불변 확인 |
| 0분산 처리 | 정상에서 `nunique() > 1`인 센서만 파생/PCA에 사용 | 현재 처리 확인. 정책 문서화 권고 |
| 매우 작은 양의 분산 | 별도의 업무상 분산 하한 없음 | 정책 보완 필요. 즉시 임의 epsilon 적용은 권하지 않음 |

## 수정 권고 1: 현재 운영 RF와 PCA 실험을 문서에서 구분

현재 CN7 운영 버전은 `rf-20261005T070541Z-eee06bbc`다. 저장 bundle을 읽어 확인한 내용:

- scenario 이름: `raw_alltrain_scaled`
- domain 변환 없음
- 실제 모델 단계: `VarianceThreshold → RandomForestClassifier`
- 추가 StandardScaler 및 PCA 없음

이 scenario 이름은 LR와 공유하는 공통 기본값이며, 이름만으로 RF에 scaler가 있다고 판단하면 안 된다.

**수정할 설명:** “현재 운영 RF가 정상 표준화와 PCA/RMSE를 사용한다”라고 쓰지 않는다. 현재 고정 운영 기준 RF와 `group_pca` 실험 후보를 구분한다. 보고서의 PCA 논리는 해당 실험 구성에 적용되는 설계 설명이다.

현재 운영 모델의 예측값 변경은 필요하지 않다. 기존 모델을 재명명하거나 저장 결과를 수정하는 작업도 이번 검토에서 수행하지 않았다.

## 수정 권고 2: RF 실험과 runtime의 도메인 변환 계약 통일

위치:

- `modeling/random_forest_manual.py`: `feature_frame`, `fit_features`
- `modeling/random_forest_cn7_integrated.ipynb` 및 RG3 대응 노트북
- `03.modeling/common/pipeline_runtime.py`: `fit_supervised`
- 공통 runtime이 사용하는 `03.modeling/models/ocsvm.ipynb`: `fit_features`, `transform_features`

현재 RF 실험 코드는 도메인 구성에서 제공 원변수를 base 열로 유지하고, 파생변수만 정상 z에서 계산한다. 상수 제거는 정상·위험 전체 train에서 적합한다.

공통 runtime은 non-raw scenario에 OCSVM 공통 변환을 사용한다. 여기서는 정상에서 활성인 base 열의 z 좌표를 사용하며, 특징 variance와 최종 feature scaler를 정상 자료에서 적합한다.

두 경로의 단순 양의 선형 스케일 차이만으로 RF 결과가 반드시 달라진다고 주장하지 않는다. 그러나 **정상에서는 상수이고 위험에서만 달라지는 입력의 보존 여부는 실제 정보 차이**다.

### 제한 재현

24개 입력의 합성 자료에서 `Injection_Time`을 정상 패턴에서는 0, 위험 패턴에서는 2로 설정하고 같은 `thermal` 이름으로 변환했다.

- RF 실험 변환: 해당 입력을 유지함.
- 공통 runtime 변환: 해당 입력을 제외함.

따라서 같은 scenario 이름이 동일 전처리 계약을 보장하지 않는다. 이 결과는 분류 성능 비교가 아니라 변환 차이의 재현이다.

**수정 방향:** RF 도메인 후보를 운영에 등록하거나 동일 설정으로 CT하려면 RF 전용 변환 정의와 artifact 형식을 공유하고, 학습·score·CT가 그 계약을 유지하도록 한다. 모델 종류와 변환 종류를 별도 기록하는 방식이 적절하다. 검증된 실험 변환을 그대로 저장·재사용하고, OCSVM 변환으로 조용히 대체하지 않는다.

현재 운영 RF는 domain=None이므로 이 차이의 직접 영향은 없다. 미래의 RF 도메인/PCA 운영 연결 전 보완 항목이다. 지금 바로 공통 LR/OCSVM 변환을 변경하면 과거 LR 감사와 모델 호환성에 영향이 있으므로 피한다.

## 수정 권고 3: 분산 처리와 계산 관례 명시

현재 코드는 완전 상수 센서를 파생/PCA에서 제외하지만, 작은 양의 분산에 별도 하한을 두지 않는다.

합성 센서의 정상 표준편차를 약 `5.97e-10`으로 만든 후 신규 값 1을 변환하자 정상 z는 약 `1.68e9`가 됐다. 이는 작은 기준 변동에 대한 큰 상대 편차의 계산이며, 그 자체로 코드 오류나 현장 성능 실패를 의미하지 않는다.

실제 CN7·RG3 8개 fold에서는 `0 < std < 1e-8`인 센서가 있는지 별도 기록했다. 임계값 `1e-8`은 점검용이며 현장 분산 기준으로 확정한 값이 아니다.

**수정 방향:** 참조집단, 패턴 동일 가중치, StandardScaler의 분산 계산 방식(ddof=0), 상수 센서 처리, 작은 분산의 기록·보류·제외 여부를 문서화한다. 업무상 하한이 필요하면 제공 좌표와 측정 해상도를 확인하고 train 기준으로 결정한 뒤 후보 버전으로 비교한다. Test 결과를 보고 하한을 고르거나 기존 모델에 임의 epsilon을 적용하지 않는다.

## 수정 권고 4: 통계 설명 보완

보고서·매뉴얼·회고록에서 다음 내용을 명시하는 것이 적절하다.

1. 추가 표준화의 목적은 RF의 필수 스케일 보정이 아니라 정상 학습 패턴의 변동 척도로 분석 공간을 정하는 것이다.
2. 정상은 실제 정상 제품 전체가 아니라 관측 자료에서 위험 이력이 없는 라벨 0 고유 패턴이다.
3. 패턴 동일 가중치 기준과 제품 빈도를 보존한 운영 드리프트 기준은 서로 다른 통계 대상이다. PCA를 제품 빈도로 적합했다고 표현하지 않는다.
4. PCA는 중심을 내부적으로 제거하므로 평균 재이동만으로 축이 달라진다는 설명은 피한다.
5. PC 2개와 RMSE는 고정 실험 설계이며 충분성·최적성을 입증한 값이 아니다.
6. 재표준화가 제공 단계 누수 부재, 원천 물리 단위 복원, 라벨/비라벨 좌표 정합을 증명하지 않는다.

첨부 문서의 선형 표준화 상쇄식은 공통 고정 선형 변환·비영 분산 조건의 설명이다. 원천 변환 방식은 확인되지 않았으므로 이 등식을 실제 원본 데이터에 대한 확인 사실로 확장하지 않는다.

## 코드로 확인한 범위

- RF 실험 파일에서 특징 변환 함수와 필요한 상수만 추출해 실행했다. 파일 전체의 학습·탐색 코드는 실행하지 않았다.
- CN7/RG3 각각 4-fold, 총 8개 실제 train/validation 변환을 확인했다.
- scaler 평균이 정상 train 평균과 일치하고 정상 표본 수가 맞는지 확인했다.
- validation 및 변경된 입력을 transform한 뒤 scaler 평균이 바뀌지 않는지 확인했다.
- PCA 수동 복원 `mean_ + scores @ components_`와 inverse_transform의 일치 및 RMSE를 확인했다.
- 합성 작은 분산과 RF/runtime 계약 차이를 재현했다.
- 현재 운영 RF artifact를 읽어 실제 변환을 확인했다.
- 실행 전후 실제 runtime과 기존 LR 결과의 파일 해시는 동일했다.

**미실행:** RF 재학습·전체 탐색·새 성능 비교·승격·CT·전체 122개 회귀 재실행. 이번 검토에 소스 변경이 없으므로 관련 변환 확인에 범위를 한정했다. 첨부 PDF가 참조하는 별도 원본 RF 모델링 보고서 12~15쪽은 이번에 직접 대조하지 않았다.

## 권장 순서

1. 현재 운영 RF와 실험 PCA 경로를 구분하는 설명, 정상 기준·단위·분산 관례를 문서에 반영한다.
2. RF 도메인/PCA 모델을 실제 운영에 연결하려는 시점에 전용 변환 계약을 통일한다.
3. 그때 실험·등록·추론·CT의 특징 동일성, 저장 변환 재사용, LR/OCSVM 호환성을 격리 검증한다.
4. 파생변수·PCA의 우열은 독립 평가 및 사전에 정한 검사 예산으로 별도 검증한다.
