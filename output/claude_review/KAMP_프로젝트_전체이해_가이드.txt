KAMP 프로젝트 전체 이해 가이드 (코드를 몰라도 흐름을 이해하기 위한 설명)
작성: Claude / 2026-10-05

1. 이 프로젝트가 푸는 문제
 - KAMP 제조 AI 경진대회. 사출성형 공정 데이터로 불량을 미리 잡는 것이 목표.
 - 제품(금형) 두 종류: CN7, RG3. 각 제품을 만들 때 기계가 남긴 공정값 24개(사출 시간, 압력, 온도 등)와 합격/불합격 라벨이 있다.
 - 대회가 요구하는 그림: 한 번 학습하고 끝이 아니라, 새 생산 데이터가 계속 들어오는 상황에서
   "판정 → 변화 감시 → 재학습 → 검증 → 교체"가 도는 7단계 운영 구조(아키텍처 그림).

2. 데이터가 어려운 이유
 - 불량이 매우 적다: CN7 1,211개 중 불량 17개, RG3 1,182개 중 25개(약 1~2%).
 - 같은 공정값인데 어떤 건 합격, 어떤 건 불합격(특히 RG3는 위험 패턴 25개가 전부 이런 경우).
   → 공정값만으로 불량을 완벽히 가르는 건 원리적으로 불가능한 부분이 있다.
 - 라벨 없는 데이터는 많다(각 3.5만 개 이상)지만 정답이 없다.
 - 생산 시각·제품 고유번호가 없다 → 시간순 분석, 같은 제품 재전송 구분이 어렵다.

3. 핵심 개념 ① 패턴 통합과 '위험 이력'
 - 24개 공정값이 완전히 같은 제품끼리 하나의 '패턴'으로 묶는다(CN7 1,211개 → 606패턴).
 - 그 패턴에서 불량이 한 번이라도 나왔으면 '위험 패턴(1)'. (예: 같은 조건 3개 중 1개 불량 → 위험)
 - 그래서 모델이 맞히는 대상은 "이 제품이 불량인가"가 아니라 "이 조건이 불량 이력이 있는 조건인가"다.
 - 원본 제품 기록(몇 개, 그중 몇 개 불량)은 지우지 않고 따로 보존한다.

4. 핵심 개념 ② 시험지 나누기(Test / 개발 4-fold / OOF)
 - Test 20%: 마지막에 한 번 보는 시험지. 고정.
 - 개발 80%를 4조각으로 나눠 돌아가며 3조각으로 공부하고 1조각으로 연습시험(4-fold). 그 연습시험 결과 모음이 OOF.
 - 모델·설정 고르기는 OOF로만 한다. Test로 고르면 '시험지 보고 공부한' 셈이 된다.
 - 문제: 지금 Test는 여러 번 열어봤다 → 더 이상 독립 시험지가 아니다. 최종 모델 판단에는 새 라벨 자료가 필요하다.

5. 모델 4종과 결과
 - IF(Isolation Forest), OCSVM: 정상만 배워서 "정상과 다르면 이상"으로 판단.
 - LR(로지스틱 회귀), RF(랜덤 포레스트): 정상과 불량을 모두 보고 구분을 배움.
 - 결과: 고정 기준선(임계값)으로 "불량/정상"을 자르면 Test에서 거의 다 실패(CN7 불량 3개를 못 잡음 등).
   하지만 CN7은 "위험한 순서로 줄 세우기"는 잘했다(OOF AUC 0.9 수준, 상위 10% 검사로 OOF 위험 11개 중 RF 9개).
 - 그래서 CN7은 '임계값으로 판정'이 아니라 '검사 예산' 방식: 배치마다 위험 점수 상위 10%만 사람이 검사.

6. CN7과 RG3를 다르게 다루는 이유
 - 간단한 위험 점수가 무작위보다 나은지 통계 검정(순열 검정)을 했다.
   CN7: 의미 있음(AUC 0.87, p=0.001) → 모델로 검사 순위를 매긴다(RF + 검사 예산).
   RG3: 무작위와 구분 안 됨(AUC 0.45, p=0.78) → 모델 판정 대신 '분포 감시'.
   제품마다 "학습 범위 밖인지, 근거가 부족한지"를 알려주고 판단 불확실 정도(높음·중간·판단 대기·낮음)로 추가 검사를 안내.
 - 둘 다 불량 확률이 아니다. "어디를 더 검사할지"를 정하는 도구다.

7. 왜 '운영 파이프라인'이 필요한가
 - 공장은 계속 생산하고, 설비·금형·원료가 바뀌면 데이터 분포도 바뀐다(드리프트).
 - 학습할 때와 분포가 달라지면 모델 판단을 믿기 어려워진다 → 변화를 감시하고, 원인이 확인되면 다시 학습해야 한다.
 - 대회 아키텍처 7단계가 바로 이 순환 구조다.

8. 운영 파이프라인의 개념(7단계)
 1~3 (만드는 단계, 10/3까지): 데이터 준비 → 패턴 통합 → 모델 학습·비교
 기준선: 학습 당시의 정상 운영 분포(공정값·모델 점수가 보통 어떤 범위에 있었는지). 이후 모든 비교의 기준.
 4 배치 수집·추론: 새 생산분이 묶음(배치)으로 들어오면 중복 확인 후 저장된 모델로 점수를 낸다.
 5 드리프트 감지: 배치를 모아(제품 200개·패턴 40개) 기준선과 비율 차이(TV 거리, 0~1)를 잰다.
   우연히 생길 수 있는 차이보다 크면(경보선) 1회 '관찰(watch)', 2회 연속 '원인 검토(review)'.
   CN7은 검사 순위, RG3는 검사 안내를 함께 낸다.
 6 재학습(CT): review가 나와도 자동으로 하지 않는다. 사람이 원인을 확인하고, 정답(라벨)이 있는 새 자료가 충분할 때만 후보를 만든다.
 7 검증·교체(CD): 후보와 현재 모델을 같은 별도 시험지로 비교해 이길 때만 교체. 문제가 있으면 롤백.
 → 교체된 모델로 다시 4단계부터 반복.

9. 오늘(10/5) 한 일 — "운영 사고가 나도 데이터가 꼬이지 않게"
 흐름의 골격은 있었지만, 팀장님 검토에서 '실제 운영에서 생길 사고'에 대한 빈틈이 지적됐다. 오늘은 그 빈틈을 메웠다.
 - 같은 배치가 두 번 들어오는 사고: 두 번 세면 공정은 그대로인데 '변화 2회 연속'으로 오판 → 재학습까지 열린다.
   → 내용·제품 ID·'제품-입력-라벨 연결'로 중복을 막는다. 같은 자료면 '이미 완료', 바뀐 자료면 '충돌'로 거부.
 - 처리 도중 멈추는 사고: 저장은 됐는데 감지가 실패하면? → 단계별 진행 상태를 기록하고, 멈춘 곳부터 이어서 처리.
   처음부터 다시 받지 않는다(재수집 금지).
 - 버전이 섞이는 사고: 안내를 다시 만들 때 그사이 모델이 바뀌었다면? → 처음 쓴 모델·기준선·정책을 고정해서 재사용.
 - 동시에 여러 작업이 도는 사고: → 운영 잠금으로 한 번에 하나만.
 - 모델 교체 중 멈추는 사고: → 새 기준선을 먼저 만들고 교체, 중간에 멈추면 운영을 막고 같은 교체를 재개.
 - 판단 표시의 오해: 표본이 부족한 '판단 대기'를 '괜찮음'으로 보여주지 않기, 검사 10%면 정확히 10%만 표시 등.
 - 그 외 운영 기준 RF 등록(CN7), 검사 자동 실행기, LR 결과 감사 방식 정비.

10. 누가 무엇을 했나
 - 팀장님: 브랜치를 보고 통계·논리·흐름 검토(2회).
 - Claude: 검토 내용을 코드와 대조, 1차~P0 수정, 테스트 추가, 작업 내역·보고서 정리.
 - Codex: 수정 결과를 장애를 일부러 일으켜 검수(5회), 남은 결함 수정과 P1·P2(버전 고정·후속 연결·잠금·교체 복구·평가 이력)·종단 리허설 구현.
 - 최종: 전체 115개 자동 테스트 + LR 감사 통과.

11. 지금 어디까지 왔나
 - 됨: 학습(1~3) + 운영 순환(4~7) + 운영 사고 대비 장치, 합성 자료로 처음부터 끝까지 리허설 성공.
 - 안 됨(코드 밖): 새 라벨 평가 자료, 현장 검사 비율 합의, 생산 시간순·좌표 확인, 현장 성능 확인.
 - 주의: 테스트 통과 = "기능이 설계대로 동작"이지 "현장에서 불량을 잘 잡는다"는 뜻이 아니다.
   CN7 RF는 '비교 기준'으로 지정한 것이지 최종 선정 모델이 아니다.

12. 자주 나오는 용어
 - 배치: 한 번에 들어오는 생산 데이터 묶음 / 패턴: 공정값이 똑같은 제품 묶음
 - 기준선(baseline): 비교 기준이 되는 정상 운영 분포 / 드리프트: 분포 변화
 - TV 거리: 두 분포 비율이 얼마나 다른지(0~1) / 경보선: 우연 수준을 넘는 변화의 기준
 - watch/review: 변화 1회 관찰 / 연속 변화 원인 검토 / waiting: 표본 부족으로 판단 대기
 - CT(지속 학습): 재학습 후보 만들기 / CD(지속 배포): 평가 후 교체 / 롤백: 이전 모델로 되돌리기
 - exact_k: 검사 비율만큼 정확히 k개만 검사 / found_TP: 그 안에서 찾은 위험 패턴 수
 - OOF: 교차검증 연습시험 결과 / 순열 검정: 결과가 우연인지 확인하는 통계 검정
 - 제품 ID 계약: A=고유 생산 ID가 있는 자료, C=ID 없는 자료(현재 대회 자료)
