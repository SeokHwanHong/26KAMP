1단계. 데이터 준비
========================================================================
[수집]
- CN7·RG3를 분리해 따로 처리. 입력 24개(data/schema/input_features.json)
- 배치 파일(CSV)에 선택적으로 PassOrFail(라벨), record_id 또는 product_id(제품 ID)
- 운영자가 '좌표·스케일 정합 확인'(--coordinates-confirmed)과 라벨 출처(--label-source)를 명시
[검사]
- 24개 열·순서·수치형·결측/무한값 확인(validate_x). 실패 → 수집 보류(held)
- 라벨이 있으면 0/1만 허용, 라벨 출처 필수
- 좌표 정합 확인이 없으면 추론·감지 보류(held). 열 이름이 같다는 것만으로 정합을 판단하지 않음
- 제품 ID 계약(사용자 결정: A 기본 + C 예외)
  A: record_id/product_id가 있으면 데이터셋 안에서 고유한 생산 ID. 문자열·정수만 허용,
     결측·빈 값·앞뒤 공백·실수형은 예약 전에 보류. 배치 안 중복 ID도 보류
  C: ID 열이 없으면 내부 '<batch_id>:<행>'을 쓰되 배치 간 비교에는 쓰지 않음. 'Unnamed: 0'은 행 번호이지 ID가 아님
  ※ 대회 원본 자료에는 생산 ID·생산 시각이 없음 → 현재 자료는 전부 C 경로
[재검사·재처리]
- 보류된 배치는 저장된 것이 없으므로 같은 batch_id로 고쳐서 다시 보내면 됨(이전 시도는 held_archive에 보관)
[출력] 보류 사유가 담긴 batches/<ID>/manifest.json(status=held)

3단계. 초기 모델·기준선
========================================================================
[수집]
- 고정 분할: Test 20%(패턴 단위, 고정) + 개발 4-fold. Test는 이미 여러 번 관찰돼 '후속 평가'로만 취급
[학습]
- IF: 정상 패턴 기준(고정 참조) / OCSVM: 정상 패턴 기준(노트북 탐색)
- LR: 8개 입력 구성 × C 15개 × 가중치 2 = 240개 설정, 임계값 1,001개, 개발 OOF로 선택 → 개발 전체 재학습
- RF: 고정 설정(나무 300, 깊이 5, 잎 최소 5, 불균형 보정). 별도 탐색 결과를 자동 등록하지 않음
- 모델마다 독립 버전으로 저장(모델 해시·스키마·sklearn 버전·학습 패턴 지문 기록). 후보 저장만 하고 운영 지정은 별도 명령
[검사]
- 학습 패턴에 Test·등록된 평가 패턴이 섞이면 저장 거부
- 모델 로드 시 해시·스키마·라이브러리 버전 불일치면 거부
[기준선]
- 개발 패턴을 원본 제품 수만큼 복원한 분포를 입력 참조로 사용(Test 미포함, 신규 배치를 정상 참조에 자동 편입하지 않음)
- 구간 정의: 값 종류 12개 이하 → 값별, 그 외 → 참조 10분위 구간. 운영 모델 점수 구간도 함께 저장
- 운영 지정(initialize) 후 기준선 생성(baseline). 지정은 '비교 기준 지정'이지 최적 모델 선정이 아님
[재검사]
- baseline-status(읽기 전용): 기준선 파일 해시·모델 버전이 운영 모델과 맞는지 확인
- LR 감사: 저장 실행 기록 재집계(240,240 설정), 선택 재현, Test 예측 재현, 선택 설정을 현재 코드로 재학습해 저장 모델과 비교
  (코드 출처는 provenance 보관본으로 확인. 과거 240개 설정 전체 재학습은 아님)
[현재 운영]
- CN7: IF + RF(rf-20261005T070541Z-eee06bbc), 기준선 baseline-20261005T070541Z-8461282d
- RG3: IF, 배치 미수집(기준선은 첫 배치 수집 시 생성)
[명령] initial --kind rf → initialize --version <ID> --reason <사유> → baseline / baseline-status

4단계. 배치 유입·추론 (수집 확정)
========================================================================
[수집 순서] (공통 운영 잠금 안에서 한 번에 하나만)
 1 모델 전환이 미완료면 거부, 현재 기준선 파일·버전 검증
 2 1단계 검사 + 제품 ID 검증
 3 중복 검사
   - 명시 제품 ID가 이전 배치와 겹치면 보류
   - ID 없이 내용(패턴별 제품·정상·불량 수 요약 해시)이 같으면 '중복 의심' 보류
   - ID가 모두 새롭고 내용만 같으면 같은 조건의 새 생산으로 수집(duplicate_note 기록)
 4 저장 전에 중복 색인에 예약 기록(이후 어디서 멈춰도 같은 자료가 다른 ID로 들어오지 못함)
 5 저장된 전처리·모델로 추론(scaler 재적합 없음) → products / patterns / predictions 저장, 모델 버전 기록
 6 장부(batch_ledger) 등록 → 처리 상태 기록(processing.json: 제품 ID-입력-라벨 연결 해시, ID 계약) → 예약 정리
[검사]
- 라벨이 있는 배치는 패턴 단위 사후 지표만 기록(비라벨에는 성능 지표를 만들지 않음)
[재검사·재전송 처리]
- 같은 batch_id 재전송: 저장된 제품 파일(해시 검증)에서 연결 해시를 다시 계산해 비교
  행 순서만 다름 → 같은 자료(이미 완료면 already_completed, 미완료면 남은 단계만 재개)
  제품 ID 교체·ID별 입력 맞바꿈·라벨 변경·ID 열 추가/제거 → conflict, 원본 유지
  자료 검증 불가(좌표 미확인·입력 오류) → rejected
  저장 제품 파일·manifest 누락/손상인데 수집 이력이 있으면 → rejected(재수집하지 않음)
  ID 계약 근거가 손상되면 C로 추정하지 않고 rejected
- 라벨 정정은 재전송으로 처리하지 않음(정정 절차는 요구사항만 문서화, 미구현)
- 중단 상태: reserved_not_stored(예약만) / commit_incomplete(파일 저장, 확정 미완료) → 같은 ID 재전송 또는 resume
[출력] runtime/<ds>/batches/<ID>/(products, patterns, predictions, manifest, processing), batch_ledger.json, dedup_index.json
[명령] ingest --input <csv> [--batch-id] [--label-source] --coordinates-confirmed / pending / resume --batch-id

5단계. 드리프트 감지 + 데이터별 결과(CN7 검사 우선순위 / RG3 안내)
========================================================================
[수집]
- 아직 감지에 쓰지 않은 accepted 배치를 누적(배치 크기와 감지 윈도 분리)
- 제품 200개·고유 패턴 40개 미만이면 waiting(판단 보류, 다음 배치까지 누적)
[검사]
- 기준선 구간으로 범주화: 입력 24개 값 + 변수 조합 2개(사출·충전 시간, 최대 사출압·금형 온도3) + 모델 점수·예측
- 표현마다 TV 거리(0~1, 비율 차이 합의 절반) 계산
- 경보선: 유효 표본 n_eff = min(참조 제품 수, 현재 고유 패턴 수)로 참조를 200회 재표집, 회차별 최대 TV의 99% 분위수
- 최대 TV가 경보선 초과 → 연속 횟수 증가. 1회 watch(관찰), 같은 기준선·같은 경보 정책에서 2회 연속 review(원인 검토), 초과 없음 normal
- 상태 의미: waiting=판단 대기, normal=경보 없음(품질 보증 아님), watch/review=검토 신호(불량 확정·자동 재학습 아님)
[데이터별 결과]
- CN7(모델 판정): 운영 RF 점수로 배치 안 제품 순위 → 검사 예산 exact_k
  k = 올림(제품 수 × 검사 비율, 기본 10%), 최소 1개(0%는 거부). 동점은 입력 지문 → 제품 ID 순으로 정확히 k개
  점수는 위험 이력 패턴 순위이지 불량 확률이 아님
- RG3(분포 감시): 제품별 근거 단계(학습 범위 밖 / 정보 부족 / 위험 이력 참고 / 관찰)와 판단 불확실 단계
  (높음: review 또는 범위 밖, 중간: watch 또는 정보 부족, 판단 대기: waiting, 낮음: normal)
  구간 위험 이력은 Wilson 95% 구간으로 표시(참조 20패턴·위험 5개 미만은 표본 부족). 불량 확률이 아님
[재검사·복구]
- 감지 결과 저장 후 소비 장부 기록 전 실패 → 다음 감지·재개 때 감지 ID 기준으로 한 번만 반영(같은 배치 재소비 없음)
- 경보 정책(분위수·반복 수)이 바뀌면 캐시된 경보선을 보관하고 재계산, 연속 횟수도 새로 셈
- 안내 실패(advice_failed) 후 재개: 최초 기록한 모델·기준선·정책 그대로 사용(현재 운영 모델로 몰래 바꾸지 않음),
  원래 근거가 없거나 바뀌었으면 명시적 실패
- waiting이었던 배치가 이후 윈도에 포함되면 배치↔감지 연결 갱신, 새 안내 revision 생성, 처음 안내는 이력으로 보존
  (재수집·윈도 재소비 없음. 후속 안내 실패는 refresh-advice로 재개)
- batch-status: '처리 완료'와 '분포 판단 확정'을 따로 보여줌
[출력] drift/<ID>.json, monitor.json, batch_drift_links.json, inspection_priority.*(CN7), inspection_advice.*(RG3),
       advice_history/<revision>, advice_latest.json
[명령] drift / batch-status --batch-id / refresh-advice --batch-id / reconcile-monitor

6단계. 모델별 CT(재학습)
========================================================================
[수집]
- review 상태의 감지 ID, 확인한 원인 기록, 해당 감지 윈도에 포함된 라벨 배치
- 기존 학습 자료 + 새 라벨 패턴을 합쳐 같은 입력은 최대 라벨로 통합(과거 위험 이력을 새 정상으로 덮어쓰지 않음)
[검사(재학습 조건)]
- review 이후에만, 원인 기록 필수, 현재 운영 모델을 기준으로, 감지 이후 모델이 바뀌었으면 새 기준선에서 감지부터 다시
- 비라벨 배치 제외, Test·등록된 평가 패턴이 섞이면 거부
- 고유 정상 30개 이상(LR·RF는 위험 5개 이상도) 필요
[학습]
- IF·OCSVM: 확인된 정상 패턴만 전체 재학습 / LR·RF: 정상·위험 전체 재학습(부분 학습 아님)
- 임계값은 부모 모델 것을 유지(평가 자료로 다시 고르지 않음). 후보로만 저장, 자동 운영 지정 없음
[재검사]
- 후보 기록에 원천 감지 ID·배치·원인·기존/신규 패턴 수 저장. 승격 여부는 7단계에서 판단
[명령] retrain --kind <if|ocsvm|lr|rf> --batch-ids ... --drift-id <ID> --cause <원인>

7단계. 검증·교체(승격/유지/롤백)
========================================================================
[수집 — 평가 자료 등록]
- 실제 라벨이 있는 분리 평가 자료를 등록. 목적: independent(승격 근거 가능) / historical_followup(근거 불가)
- 학습 이력이 있는 패턴은 독립 평가로 등록 거부, 기존 Test 패턴이 있으면 강제로 historical_followup
- 평가 CSV에서 입력 지문을 다시 계산해 저장 열·manifest와 대조, 라벨 0/1 확인, manifest 해시 고정
- 같은 내용을 새 ID로 재등록하면 이전 평가 ID와 연결(독립성이 새로 생기지 않음)
[검사 — 평가]
- 평가 직전·승격 직전 모두 평가 기록·목적·자료 해시 재확인
- 평가 고유 정상 30개·위험 5개 미만 → 보류
- CN7(검사 예산 모드): 같은 평가 자료, 같은 검사량(exact_k)에서 위험 이력 패턴 발견 수(found_TP)로 비교
  · 예산 내 최대 발견 가능 수 min(실제 검사 수, 위험 수)의 50% 이상
  · 운영 모델이 있으면 그보다 많이 찾아야 함
  · all_ties 평가는 참고 전용(실제 검사 수가 달라 같은 검사량 비교가 아님) → 선정·승격 불가
- CN7 모델 선정(select-cn7): LR·RF·OCSVM 후보를 같은 자료로 비교. 선정에 쓴 자료(또는 겹치는 패턴)로는 승격 불가
- 그 외(threshold 모드): F1 개선 + 재현율 유지 + 오탐률 0.2 이하 / IF: 같은 검사량 발견 기대 수 개선
[교체]
- 통과한 해당 모델만 명시적 승격(promote). 미달·표본 부족이면 기존 모델 유지
- 전환 순서: 새 모델 출력 기준선을 먼저 준비(입력 참조는 개발 분포 유지) → 레지스트리·기준선 포인터 기록
  전환 기록(transition_pending): preparing → prepared → completed
[재검사·복구]
- 기준선 준비·포인터 기록 중 실패 → 전환 미완료로 남고 추론·감지·CT·평가를 차단, resume-transition으로 같은 전환 재개
- 롤백(rollback): 승격 이력에서 이전 버전으로 같은 전환 절차를 거쳐 복원(사유 필수)
- 승격 직전 평가 후 모델·자료·운영 모델이 바뀌었으면 거부(재평가 필요)
[명령] register-evaluation / evaluate / select-cn7 / promote / rollback / resume-transition

- 잠금 순서: 운영 작업 잠금(.operation.lock) → 수집 잠금 → 기록 잠금. 수집·감지·평가·전환이 동시에 돌지 않음
  잠금이 남으면 작업 종료 확인 후 unlock --lock <operation|ingest|writer> --reason <사유>

- 검사 실행: run_checks_only.bat(운영 무변경, 종료 코드 0 통과 / 1 실패 / 2 실행기 오류)

검증 범위와 한계 (보고 시 구분)
========================================================================
- 전체 115개 테스트: 운영 12 + 등록/LR 8 + OCSVM 24 + 판단·복구·재전송 58 + 운영 계층 13. 합성 자료로 기능·장애 복구 확인
- 격리 종단 리허설(CN7/RG3): 초기 기준 → 라벨 배치 → watch/review → 원인 확인 → LR 후보 → 평가 보류/유지 → 통과 후보 → 승격 → 롤백
  (모든 모델 조합을 종단으로 검사한 것은 아님)
- 미확인 외부 조건: 생산 시간순(연속 경보는 배치 도착 순서 기준), 좌표 정합, 독립 실제 라벨, 현장 검사 비율·누락 허용량, 현장 성능
- CN7 RF는 비교 기준 지정. 최종 모델 판단은 독립 평가 자료(위험 5개 이상) 확보 후
