2. 검토에서 확인한 문제
======================================================================
[문제 1] RG3 재검사 권고가 100%다 (가장 중요)
- 기존 규칙: 제품이 걸친 구간 중 하나라도 과거 위험이 1건 이상이면 재검사 권고.
- 26개 변수·조합 구간을 보므로 거의 모든 제품이 어딘가에 걸린다.
- 실행 결과: RG3 Test 119/119, RG3 개발 OOF 472/472, CN7도 100% 재검사.
- Codex 보고서도 "검사량을 줄이지 못한다"고 인정했다. 판단 정보가 없는 경보다.

[문제 2] 구간 위험 이력에는 RG3 예측력이 없다
- Wilson 하한이 전체 위험 비율보다 높은 구간만 남겨도, 개발 OOF에서
  39%를 표시해 위험 20개 중 10개 포함(무작위 대비 약 1.3배), Test에서는 61개 표시·위험 0/5.
- 개발 OOF 순열 검정: RG3 AUC 0.451, p 0.776 → 무작위와 구분 안 됨.
→ 구간 위험 이력을 재검사 근거로 쓰면 근거 없는 경보가 된다.

[문제 3] 같은 배치 재전송 문제(이전 보고서 P2)가 그대로다
- 원본 pipeline_runtime.py를 수정하지 않았으므로 같은 로트를 두 번 보내면
  지속 변화(review)로 집계되어 재학습이 열리는 문제가 남아 있었다.

[문제 4] CN7 선정에 쓴 평가 자료로 승격까지 할 수 있다
- select-cn7은 평가 자료 A로 3개 모델 중 하나를 고르는데, 같은 A의 평가 결과로 promote가 가능했다.
- 고른 자료로 다시 합격 판정을 하면 선택 편향 때문에 성능이 과대평가된다.

[문제 5] 데이터 유형(CN7형/RG3형) 판정 근거가 코드·문서에 없었다
- 데이터셋 이름으로만 분기하고, 왜 그렇게 나누는지 재현 가능한 근거가 없었다.

3. 수정 내용 (pipeline_runtime.py 미수정)

[03.modeling/common/decision_runtime.py]
1) RG3 근거 단계 재설계
   out_of_reference(학습 범위 밖 값·미관측 값/조합) → 추가 검사 권고
   insufficient_information(걸친 모든 구간이 표본 부족) → 추가 검사 권고
   elevated_risk_history(Wilson 하한 > 전체 위험 비율) → 참고 표시(기본은 재검사 아님)
   monitor → 관찰, 정상 보증 아님
   정책값 rg3_history_triggers_recheck(기본 False)로 위험 이력 재검사를 켤 수 있음.
2) 배치 단위 드리프트 안내(batch_advice): review → 샘플 검사 상향·원인 확인, watch → 관찰.
3) 배치 중복 차단: 이전 배치와 내용 해시 동일 또는 제품 ID 중복이면 held.
   runtime/<dataset>/dedup_index.json에 색인. 이전 보고서의 duplicate_batch_fix.patch는 이것으로 대체.
4) 선정에 사용한 평가 자료로 promote 차단. select-cn7 보고서에 검사 예산(상위 10%) 탐지 수를 참고로 추가.

5. 남은 한계와 결정 필요 사항
======================================================================
- RG3 재검사 6건 중 Test 위험은 1건이다. 이 정책은 "불량을 찾는 장치"가 아니라
  "모델·구간 근거가 없는 조건을 걸러 내는 안전장치"다. 그렇게 설명해야 한다.
- 구간 위험 이력으로 재검사를 할지는 현장 검사 비용과 합의할 사항이다(옵션으로 남김).
- CN7 최종 선정은 별도 평가 자료 2개(선정용·승격용)가 있어야 완결된다. 현재 자료로는 불가.
- 제품 ID 없는 배치는 내용 해시로만 중복을 판단한다. 운영 배치에는 제품 ID를 넣는 것을 권장.
- 이전 보고서의 P3 항목(비트 단위 비교, 미완료 실행 폴더 선택 등)은 이번 범위에서 수정하지 않았다.
