보고서 대상 커밋은 `9c953eef54a9dc9cfccd1c9266cdfbf5c647c422`, 현재 로컬 HEAD는 `2fa27483407289fd72ec53447144e54716da9815`다.
보고서 결과를 현재 PC에 그대로 적용하지 않고 해당 코드 경로와 환경 차이를 확인했다.

## 즉시 보완할 실행·복구 항목

| 항목 | 현재 로컬 확인 | 대응 방향 |
|---|---|---|
| RF의 pyarrow 의존성 | 현재 PC에는 설치돼 있지만 requirements에는 빠져 있다. 별도 프로세스에서 해당 모듈을 차단하면 저장 RF 로드 실패, IF는 성공 | 현재 artifact에 필요한 의존성을 선언하고 깨끗한 환경에서 저장 모델 로드 및 추론 검증. 기존 artifact를 임의로 다시 저장하지 않음 |

| 구형 평가 재등록 | 기존 평가의 integrity를 제거한 격리 상태에서 새 평가 등록이 실패하고 새 폴더가 남는 것 재현 | 기존 증거를 보존하는 명시적 이관, 등록 전 사전 검증 또는 등록 상태 저널, 실패 재시도 복구 마련 |
| 줄바꿈과 LR 소스 감사 | 현재 PC LR source는 LF이며 기록된 바이트 해시와 일치. CRLF 체크아웃에서는 바이트 값이 달라질 수 있는 규칙 확인 | 소스 줄바꿈/해시 정책과 불변 산출물 바이트 정책을 구분. 과거 실행 기록 수정 없이 줄바꿈만의 차이와 실제 코드 변경을 구별 |

경보 연속성 재현은 경보선 0/1을 주입하여 조건을 통제했으며 실제 detect·배치·장부 경로를 실행했다. 새 경보선의 통계 성능 비교는 아니다.

구형 평가에 integrity 파일만 새로 만들어 검증된 독립 자료로 승격시키는 방식은 피한다. 원래 용도·학습/선정 중복·원천 라벨 근거를 검증하고, 근거 부족은 legacy_unverified 등 보류 상태로 남기는 정책이 필요하다.

줄바꿈 감사도 모든 해시 검사를 느슨하게 해서는 안 된다. 소스만 명시적 줄바꿈 규칙을 적용하고 모델·평가·불변 실험 결과는 바이트 무결성을 유지한다. 실제 함수 변경이 감사에서 검출되는 대조군을 포함한다.

## 문서 진입점 통일

현재 CLI와 운영 노트북은 workflow_runtime을 사용한다. DATASET_DECISION_POLICY 앞부분에는 decision_runtime을 운영 진입점으로 안내하는 과거 문구가 남아 있다.

- 공식 운영: WORKFLOW_ACCEPTANCE → CLI / 운영 노트북 → workflow_runtime.
- 공통 내부 구현: decision_runtime / pipeline_runtime.
- 모델 학습과 후보 생성: 모델별 매뉴얼과 노트북.
- 연구 실험·과거 기록: modeling 및 날짜별 output.

최신 진입점을 문서 첫머리에 명시하고 과거 경로를 이력 또는 연구용으로 구분한다. 팀원이 하위 모듈을 직접 호출해 공통 잠금·전환 복구를 우회하지 않도록 한다.

## 프로젝트 역할은 다음처럼 정리하는 것이 적절함

### CN7

현재는 RF를 초기 검사 모델 기준으로 유지하고 exact_k 검사 우선순위를 제공한다. LR/OCSVM 비교는 후보 판단 근거다. 선정 보고서가 생성됐다는 사실만으로 검사 모델이나 정책을 자동 변경하지 않는다.

장기적으로 최적 모델의 검사 역할 전환을 지원하려면 모델 종류·버전·검사 정책을 함께 승인·전환·롤백하는 계약을 마련한다. 현재 단계에서 자동 최적 모델 교체를 새로 넣기보다 역할을 명시하는 것이 우선이다.

패턴 발견 성과와 제품 불량 발견 성과를 분리한다. 같은 조건 제품 100개 중 불량 1개라면 위험 패턴을 찾았다는 결과가 실제 그 불량 제품을 검사했다는 뜻은 아니다. 현장에서는 동일 검사 수로 발견한 실제 불량 수, 미탐, 오탐/불필요 검사, 비용을 평가해야 한다.

### RG3

현재 목표는 분포 감시와 검사 지원으로 유지한다. 구간·변수 변화와 범위 밖·정보 부족을 설명하며, 불량 확률이나 공정 설정 추천으로 확대 해석하지 않는다.

review의 높은 불확실성 표시는 배치 전체에 적용되므로 이를 전체 전수검사 지시로 곧바로 해석하지 않는다. 현장 검사 여력에 맞춰 우선검사와 무작위 표본검사의 실행 기준을 정한다.

현재 기준선 포인터 부재는 운영 준비 과제다. 실제 생산 자료의 좌표·검사 라벨을 확인하고 준비 또는 복구해야 하며 검토 과정에서 임의로 생성하지 않았다.

## 피드백 정책의 권장 방향

현재 입력 기준선과 RG3 구간 참조는 원래 개발 자료를 유지한다. CT 후 새 모델의 출력 기준만 바뀐다.

따라서 현재 구조를 “새 공정에 자동 적응하는 검사 안내”로 설명하면 안 된다. “고정 초기 기준과의 변화를 감시하고, 확인된 라벨로 모델 후보를 재학습한다”가 정확하다.

현 단계에서는 고정 기준을 유지한다. 새로운 정상 공정이 검사 근거로 확인된 뒤에만 승인된 별도 참조 버전을 만들 수 있게 설계한다. 모델 교체와 입력 참조 교체를 독립 작업으로 다루고 각각 근거·평가·롤백을 기록한다. 변화한 배치를 자동으로 정상 기준에 흡수하지 않는다.

과거 위험 이력은 계속 보존한다. 최근 상태 적응이 필요하면 최근 학습 자료 선택 정책을 별도로 정의한다. 과거 이력 저장소와 현재 학습 대상의 역할을 구분하되, 실제 시간 정보 없이 행 번호로 기간을 만들어내지 않는다.

## 사람의 승인 절차

review는 원인 조사 시작 신호로 둔다. CT 승인 기록에 아래를 연결한다.

1. 바뀐 변수·조합·출력 표현과 감지 ID.
2. 공정 변화인지 입력·센서·좌표 오류인지 확인한 근거.
3. 영향을 받는 모델과 재학습 모델을 선택한 이유.
4. 정상 공정 확인, 실제 검사 라벨 출처, 학습 배치.
5. 별도 평가 자료와 검사 예산, 승인자 및 실패 시 유지 조건.

선정·학습·평가·승격 역할을 분리하고, 표본이나 근거가 부족하면 유지한다. 자동 인과 판정이나 자동 배포를 새로 요구하지 않는다.

## 작업 순서와 인수 기준

1. **실행·복구 4건 보완:** 모델 로드, A→B→A, 구형 자료 보존/재등록, LF/CRLF 및 실제 코드 변경 대조 검사.
2. **공식 문서와 역할 통일:** CN7 RF 초기 기준, RG3 감시 범위, 모델과 참조 갱신의 의미를 명시.
3. **격리 종단 검증:** 현재 정책과 같은 모델 경로로 수집→감지→검토→CT 후보→평가 보류/유지 또는 명시적 교체→롤백. 운영/LR 원본 보존.
4. **현장 검증 계획:** 원천 ID·생산 시간·좌표 정합·실제 라벨·독립 평가 확보 후 제품 단위 동일 검사량 성과와 비용 확인.
5. **RF 실험 운영 연결:** 앞선 RF 검토에서 확인한 실험/공통 runtime 변환 차이와 CT 설정 보존을 검증한 뒤 별도 후보로 연결.

인수 표현은 “사람이 원인·라벨을 확인하고 명시적으로 재학습·평가·전환하는 로컬 운영 파이프라인”으로 제한한다. 실제 제품 성과와 최근 공정 적응 완료는 현장 검증 이후 판단한다.

## 이번 확인의 범위

PDF 전체 텍스트·9개 렌더 페이지를 검토했고 현재 코드·문서·환경을 대조했다. 정책 복귀와 구형 평가 문제를 격리 재현하고 RF 모듈 의존성을 별도 프로세스에서 차단해 확인했다. 소스·운영 runtime·기존 LR 결과는 수정하지 않았으며 재현 전후 파일 해시는 동일했다.

첫 격리 재현은 기본 시스템 임시 폴더의 접근 거부로 실행되지 않았다. 작업 폴더 내부의 별도 tmp 상태로 재실행해 결과를 확보했다. 이 환경 오류를 제품 결함으로 분류하지 않았다.

이번에 전체 122개 회귀나 LR 전체 감사를 다시 실행하지 않았다. PDF가 인용한 과거 테스트와 이번 제한 재현을 구분한다. PDF 8쪽도 앞선 실행 결과를 인용한 검사와 이번 정적 확인의 범위를 구분하므로 “9쪽 검토에서 전 경로를 새로 검증했다”고 해석하지 않는다.
