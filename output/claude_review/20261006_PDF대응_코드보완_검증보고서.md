### 2. 정책·기준선 복귀의 연속 경보

정책/기준선 A→B→A 복귀는 새 연속 구간이다. 정책에는 persistence와 continuity_version=2를 포함해 이전 계산 규칙에서 생긴 횟수도 이어 쓰지 않는다.

### 3. 구형 평가와 실패 등록 복구

신규 등록 전에 기존 평가의 CSV·지문 정합성을 확인한다. 무결성 기록이 없는 구형 자료가 있어도 겹치지 않는 새로운 평가를 등록할 수 있다.
구형 자료와 패턴이 겹치면 historical_followup으로 제한하여 독립 평가를 주장하지 않는다.

등록 자료를 evaluation_staging/<ID>에서 준비하고 manifest·integrity 검증 뒤 evaluations/<ID>로 폴더를 전환한다.
실패한 준비 폴더가 공식 평가·학습 보호 목록에 섞이지 않는다. 같은 입력·출처·purpose·ID로 재시도하며 다른 자료로 준비 기록을 교체할 수 없다.

명시적 migrate-evaluation은 구형 원본을 수정하지 않고 후속 평가 사본을 만든다. 원본 manifest/CSV 해시와 이관 사유·출처를 새 기록에 연결한다.
이관은 원래 실행 시점의 무결성이나 독립성을 소급 증명하지 않는다. 원본 CSV/manifest까지 손상된 경우에는 이관을 거부한다.

신규 CLI:

```text
evaluation-registration-status
register-evaluation --evaluation-id <실패 준비 ID> --input <같은 CSV> --label-source <같은 출처>
migrate-evaluation --evaluation-id <구형 ID> --label-source <출처> --reason <사유> --new-evaluation-id <새 ID>
```

실제 운영 평가를 이관하거나 삭제하지 않았다. 해당 동작은 모두 별도 tmp 상태에서 검사했다.

### 4. LF/CRLF 소스 감사

source_provenance.py는 기록된 바이트 해시와 정확히 일치하는 경우 또는 uniform LF/CRLF 변환만 일치하는 경우를 구분해 기록한다.
들여쓰기, 이름, 함수 내용 또는 다른 공백을 일반적으로 정규화하지 않으며 실제 코드 변경은 실패한다.

LR 감사는 모델 학습 스크립트와 보관된 runtime 소스에 이 규칙을 적용한다. runtime의 학습 정의 AST 대조와 선택 설정 재학습 재현은 그대로 수행한다.
모델·평가·기존 LR 산출물은 기존 바이트 해시 검증을 유지한다. 과거 run_config나 artifact 해시는 수정하지 않았다.
.gitattributes에 Python 소스 LF와 runtime/LR/provenance의 바이트 보존 규칙을 선언했다. git renormalize를 실행하지 않았다.
