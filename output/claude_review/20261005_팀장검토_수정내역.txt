[무엇을 어떻게 고쳤나]
F01 같은 파일 행 순서만 바꿔 재전송 → 이제 같은 내용으로 인식
  - 내용 지문을 "패턴별 제품 수·정상 수·불량 수" 요약으로 만들어 행 순서와 무관하게 함
  - 제품 ID가 1차 근거. ID가 없고 내용이 같으면 '중복 의심'으로 보류
  - ID가 모두 새롭고 내용만 같으면 다른 생산 건으로 수집하고 duplicate_note에 기록

F02 저장은 됐는데 감지에서 오류 → 수집 유지 + 못 끝낸 단계만 재실행
  - 수집 확정(파일·장부·중복 색인) → 분포 감지 → 검사 안내, 단계를 batches/<ID>/processing.json에 기록
  - 실패해도 수집은 그대로. 같은 batch_id로 다시 보내거나 resume 명령 → 실패한 단계만 다시 실행
  - 다른 batch_id로 다시 보내면 중복으로 보류(두 번 집계되지 않음)
  - 같은 batch_id에 다른 내용 → conflict로 거부, 기존 배치 보호
  - 보류(held) 배치는 같은 batch_id로 다시 보낼 수 있음(이전 시도는 held_archive에 보관)
  - 이미 끝난 배치를 다시 보내면 already_completed로 알리고 아무것도 바꾸지 않음

F03 두 작업이 동시에 같은 배치 등록 → ingest 잠금 추가
  - 중복 검사부터 등록·감지·안내까지 한 번에 하나만 실행
  - 남은 잠금 해제: pipeline_cli.py --dataset <cn7|rg3> unlock --lock ingest --reason <사유>

F04 표본 부족(waiting)이 '불확실성 낮음'으로 표시 → '판단 대기'로 분리
  - 범위 밖 값·정보 부족 같은 제품 자체 근거는 그대로 높음/중간으로 표시

F05 검사 10%인데 동점이면 전부 표시 → 동점 규칙 하나로 통일
  - 기본 exact_k: 정확히 예산 수만 표시, 동점은 record_id 순으로 잘라 재현 가능
  - all_ties(선택): 동점 전부 표시 + 예산 초과 수 기록, 평가도 같은 기준
  - 배치(제품 단위)와 평가(고유 패턴 단위)의 단위를 결과에 표시

F06 경보 기준을 바꿔도 예전 경보선 사용 → 캐시에 정책 서명 기록
  - 분위수·반복 수·기준선·코드 해시가 다르면 예전 캐시를 calibration_archive로 옮기고 다시 계산

F07 평가 자료 용도(purpose)를 바꿔도 모름 → 등록 시 지문 고정, 평가·승격 때 대조
  - 이 기능 도입 전 등록한 평가 자료는 다시 등록해야 함(현재 운영 runtime에는 평가 자료 없음)
