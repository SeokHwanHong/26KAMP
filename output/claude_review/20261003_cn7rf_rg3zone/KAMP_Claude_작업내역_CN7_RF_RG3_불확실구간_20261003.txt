1. CN7: 랜덤 포레스트 + 검사 예산
======================================================================
[모델 선택 근거] 개발 OOF만 사용, Test 미사용, 개발 위험 11개
| 모델 | OOF AUC | 상위 5% | 상위 10% | 상위 20% |
|---|---|---|---|---|
| RF (운영 고정 설정) | 0.940 | 5개 | 9개 | 11개 |
| LR (튜닝된 설정) | 0.882 | 6개 | 8개 | 9개 |
| OCSVM (선택 설정) | 0.798 | 4개 | 4개 | 7개 |
- RF가 가장 많이 찾았다. 상위 5%에서만 LR이 1개 많다.
- LR은 설정을 튜닝한 결과의 OOF라 낙관적일 수 있다. RF는 튜닝 없는 고정 설정이다.
- 위험이 11개뿐이라 1~2개 차이는 우연일 수 있다.

[구현 내용]
- 기본 판정 방식을 budget(검사 예산)으로 바꿨다. 운영 모델 종류의 기본값은 rf.
- 배치가 들어오면 RF 위험 점수로 순위를 매기고, 상위 10%(기본) 제품을 검사 대상으로 표시한다.
  산출물: 배치 폴더의 inspection_priority.json / csv / txt
  - csv: 제품 ID, 패턴 지문, 위험 점수, 순위, 검사 여부, 모델 버전
  - 경계에서 점수가 같은 제품은 모두 포함하므로 표시 수가 예산을 넘을 수 있다.
- RF 운영 모델이 지정되지 않았으면 status=no_active_model로 알린다(조용히 넘어가지 않음).
- 평가·승격 기준(budget 모드)
  - 같은 평가 자료, 같은 검사량에서 찾은 위험 수로 비교한다.
  - 예산 안에서 찾을 수 있는 최대 수 min(검사 수, 위험 수)의 50% 이상을 찾아야 한다.
  - 운영 모델이 있으면 그보다 많이 찾아야 한다.
  - 고정 임계값 기준(F1·recall·precision)은 이 모드에서 쓰지 않는다.
- select-cn7(budget 모드): 같은 검사량에서 위험을 더 많이 찾은 순으로 고른다.
  동률이면 단순한 모델(LR → RF → OCSVM) 순.
- 이전 고정 임계값 정책은 --cn7-mode threshold로 계속 쓸 수 있다.

[CLI 옵션 추가]
- --cn7-mode budget|threshold (기본 budget)
- --inspection-fraction 0.1 (배치당 검사 비율)
- --min-budget-capture 0.5 (평가 시 최소 발견 비율)

[운영 시작 순서]
python 03.modeling/pipeline_cli.py --dataset cn7 initial --kind rf
→ 생성된 RF 버전 확인
→ python 03.modeling/pipeline_cli.py --dataset cn7 initialize --version <RF버전> --reason <사유>
→ python 03.modeling/pipeline_cli.py --dataset cn7 ingest --input batch.csv --coordinates-confirmed
※ 이번 작업에서는 사용자 runtime에 RF를 등록·지정하지 않았다(운영 포인터 변경 금지 원칙).

======================================================================
2. RG3: 드리프트 기반 불확실 구간
======================================================================
[왜 "위험도"가 아니라 "불확실 정도"인가]
- 개발 OOF 순열 검정에서 구간 위험 이력 점수는 무작위와 구분되지 않았다(AUC 0.451, p 0.776).
- 따라서 "이 구간은 불량 위험이 높다"고 말할 근거가 없다.
- 드리프트로 말할 수 있는 것은 "학습 때와 다른 조건이라 판단 근거가 약하다"이다.

[구현 내용]
- 제품별 불확실 단계(uncertainty_level)
  | 단계 | 조건 | 안내 |
  |---|---|---|
  | 높음 | 드리프트 review(2회 연속 변화) 또는 학습 범위 밖 값 | 추가 검사 권고 (review면 배치 전체) |
  | 중간 | 드리프트 watch(1회 변화) 또는 정보 부족 | 관찰·샘플 검사 유지 |
  | 낮음 | 위 해당 없음 | 관찰 (정상 보증 아님) |
  | 참고 | 과거 위험 이력이 평균보다 높게 관측된 구간 | reference_note=true로 표시만 |
- 배치별 불확실 구간(uncertainty_zones)
  - 드리프트에서 분포가 가장 많이 바뀐 변수·조합 상위 8개
  - 각 구간의 변화량, 경보선 초과 여부, 범위 밖 값 개수
  - 불량 원인·불량 범위가 아님을 함께 기록한다.
- 산출물: 배치 폴더의 inspection_advice.json / csv / txt
  (불확실 단계별 건수, 불확실 구간, 제품별 [높음/중간/낮음] 메시지)

[실제 자료 예시] 기존 Test 119개 패턴에 개발 참조 적용, 드리프트 없음 가정
- 재검사 권고 6개(학습 범위 밖), 참고 표시 58개, 관찰 55개
- 새 현장 배치 검증이 아니며, 불량 발견률이 아니다.
