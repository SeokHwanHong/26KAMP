KAMP 팀 공유 테스트 플로우

1. 환경/위치
프로젝트 루트에서 실행한다. 03.modeling/requirements_operations.txt는 검증한 환경의 버전이다.
원본·스키마·전처리 분할·runtime의 IF 정렬 산출물·LR 실행 결과가 필요하다.
최신 공유 ZIP에 포함돼 있다. 원본 데이터·분할·운영 포인터를 먼저 보존한다.

2. 한 번에 검증
python 03.modeling/tests/run_checks.py
(또는 프로젝트 루트 run_checks_only.bat 더블클릭: 운영 runtime 변경 없음, 종료 코드·버전·해시 기록)
결과: output/test_runs/<고유실행ID>/summary.json 및 단계별 로그.
테스트 수는 실제 실행 출력에서 집계하고 LR 저장 결과도 재검산한다. 테스트 산출물은 output/operations_tests/<같은 실행ID>/에 분리 저장된다. 전체 LR 탐색이나 운영 교체는 하지 않는다.
runtime_unchanged=true인지 확인한다. 한 단계라도 실패하면 전체 passed=false다.

3. 내부 순서
A. test_operations.py: 배치 전처리 → 추론 → 누적 대기 → 지속 변화 → 네 모델 CT
   → 평가 분리 → 승격 조건 → 교체/롤백 및 거부 조건. 12개, 격리 합성 테스트.
B. test_registration_and_logistic.py: 감사 파일 일치·임계값·분할·변환·예측 검증, 노트북 LR 코드 동기화. 8개.
   확률은 허용오차 1e-12로 비교하고 위험 판정(p>t)은 완전 일치를 요구한다(PC 환경 차이 대응).
C. test_existing_ocsvm.py: 노트북 내부6개 × CN7/RG3 × original/if_desc. 24회.
D. audit_logistic_runs.py: 완료된(audit.json·registered_candidate.json 있는) 최신 LR 실행의 240,240개 설정/임계값 기록 재집계,
   선택·OOF·학습/검증 분리·저장 예측·현재 소스 해시 확인. 과거 LR 실행 폴더에는 파일을 추가하지 않는다.
E. test_decision_runtime.py: CN7 RF 검사 예산·RG3 불확실 단계·배치 중복 차단·선정/승격 자료 분리·잠금 해제 17개
   + 팀장 검토 F01~F07 회귀 11개(행 순서 재전송, 감지/안내 실패 후 재시도, 동시 수집 잠금, 판단 대기,
   동점 규칙, 경보선 캐시 정책, 평가 용도 기록 변경)
   + Codex 검수 추가 7개(수집 확정 도중 실패 4종 복구·중복 차단, 실행·평가 동점 선택 일치, 검사 비율 0% 거부)
   + Codex 2차 검수 2개(중단된 예약 배치에 같은 ID로 다른 자료 재전송 차단)
   + 팀장 2차 검토 1차 작업 12개(R01 감지 소비 장부 장애 4종·경보 정책별 streak, R02 완료 배치 연결 보호·ID 없는 경로·새 생산,
     R03 all_ties 선정·승격 차단, 작은 배치 exact_k, 읽기 전용 기준선 상태)
   + 1차 Codex 검수 보완 2개(연결 해시 없는 기존 완료 배치를 저장 제품 파일로 검증, A 계약 ID 결측·빈 값·자료형 거부)
   + 재전송 비교 조합 표 3개(ID 출처 4 × 재전송 7 × 단계 3, 이전 형식 기록, 증거 파일 상태 4종: 하위 사례 104개). 54개.
   LR 감사(D)는 pipeline_runtime.py가 바뀐 경우 provenance 보관본으로 출처를 확인하고 학습 경로 정의 동일성을 검사한다.
   또 선택된 설정을 현재 코드(노트북 학습 정의 포함)로 다시 학습해 저장 모델과 예측을 비교한다(탐색 전체 재현은 아님).

4. 전체 모델링 학습을 다시 재현해야 할 때
python 03.modeling/models/logistic_regression.py --dataset both
개발4-fold → 입력구성/C/가중치/임계값 탐색 → 선택 고정 → 개발 전체 재학습
→ Test 후속 평가 → 계수·구간 안내·감사 → 초기 후보 저장 순서다.
운영 모델을 자동 지정/교체하지 않는다. 실행은 고유 폴더에 저장된다.
이후 2번 검증을 다시 수행한다. 소스가 바뀌면 과거 실행을 현재 소스로 생성한 것처럼
표시하지 않는다. 해시 불일치는 원인을 확인하고 새 실행으로 재현한다.

5. 노트북

03.modeling/04_operations.ipynb: 기본값 상태 조회, 변경 작업은 명시적으로 호출한다.

6. 통과의 의미
기술 테스트 통과 = 코드가 해당 검증 조건에서 동작함.
현장 성능 검증 = 독립적인 실제 생산/검사 자료에서 운영 효과를 확인함.
둘은 다르다. 현재 LR 결과는 CN7 Test 누락3, RG3 정상 오탐110으로 운영 우위 근거가 없다.
현재 테스트의 합성 데이터·과거 관찰 Test를 신규 현장 증거로 제시하지 않는다.
